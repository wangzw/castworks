# 审批决定绑定工具调用内容摘要

## 背景

Claude Code 在执行工具调用之前触发 `PreToolUse` hook：hook 可以允许、拒绝或以 `defer` 推迟决定，推迟的调用在会话续接时以同一工具调用再次触发 `PreToolUse`；hook 允许时可以返回 `updatedInput`，以修改后的输入执行工具（[REF-claude-code-hooks](../references.md)）。平台的审批 hook 把待决调用上报为审批请求，[审批人](../glossary.md)经[人类通道](../glossary.md)提交决定，决定经定向投递交还 hook。

审批人据以决策的是工具调用的内容：工具名与工具输入。审批请求与审批决定只以不透明的 `permission_id` 关联时，审批人看到的内容没有权威来源，放行的调用可以与审批人所见不一致。会话记录位于[工作区](../glossary.md)内，[运行实例](../glossary.md) uid 下的进程可以改写；续接时 hook 输入中的工具输入来自会话记录。托管 hook 查询的一次性核对只按事件标识接受，不比对工具输入。被提示注入控制的 Agent 因而可以先以无害的输入请求审批，在 `defer` 续接之前改写会话记录中的工具输入，让获批的决定放行另一份输入。

## 考虑过的选项

### 只以 permission_id 绑定

采用它意味着审批请求与决定只携带 `permission_id`，审批人在别处查看调用内容。**被拒**：审批人看不到权威内容；续接时实际执行的输入可以被替换，决定照样放行。

### 呈现内容取自会话记录或 hook 旁路

采用它意味着人类通道从工作区的会话记录或沙箱内的 hook 旁路读取待决调用的内容。**被拒**：两种来源都由 Agent 控制，呈现的内容可以与请求审批时不同。

### 续接时以控制面保存的原始输入替换 hook 输入

采用它意味着续接时 hook 以 `updatedInput` 把工具输入换回首次请求审批时保存的内容。**被拒**：`updatedInput` 承载的是审批人对输入的修改；用它把 Agent 的输入静默换回原值，会掩盖内容被改写的事实，Agent 看到的调用与实际执行的调用也不再一致。

### 首次触发时捕获内容与摘要，决定携带所见内容的摘要，交付前重算比对

采用它意味着[看守进程](../glossary.md)在首次 `PreToolUse` 时捕获规范化的工具输入与摘要，控制面保存并作为呈现来源，审批决定携带审批人所见内容的摘要，看守进程交付决定前重算比对。**采用**——见决策。

## 决策

采用审批决定绑定工具调用内容摘要：

- 看守进程在首次 `PreToolUse` 时以规范 JSON 编码工具输入，计算其 SHA-256（[审批内容摘要](../glossary.md)，协议字段 `input_hash`），随审批请求上报工具名、内容与摘要；内容超过 `S_tool_input` 时只上报前缀，摘要仍对完整内容计算。
- `runcontroller` 把待决审批的内容与摘要保存于 `approval_request`，作为呈现的唯一来源，经 `GetPendingApproval` 与 `ListPendingApprovals` 提供给 `humanchannel`。
- 审批决定携带审批人所见内容的摘要 `input_hash`；定向投递只送达摘要等于保存值的决定，不等时按未定向事件处理。
- 看守进程在交付决定之前重算当前 hook 输入的摘要，与决定携带的摘要不一致即拒绝该次调用；续接时的工具输入来自 Agent 可写的会话记录，按不可信处理。
- 架构不变量 I12（审批内容一致）以本决策为依据。

## 后果

本决策使项目承担以下义务（穷举）：

- 审批请求携带工具名、内容与摘要；超过 `S_tool_input` 的内容只携带前缀，前缀长度为 `S_tool_preview`。
- `runcontroller` 保存待决审批的内容与摘要，提供只读查询，在审批关闭时记录关闭时刻。
- `humanchannel` 呈现时转义控制字符、双向文本控制符与终端转义序列，完整展示或明示截断并提供完整查看，标明内容由 Agent 产生，并在决定中写入审批人所见内容的摘要；文本通道的决定携带摘要前缀。
- 规范 JSON 编码由同一函数实现，看守进程在请求审批与交付决定时都使用它，各版本之间保持稳定。
- `updatedInput` 原样交给 Claude Code，比对以首次捕获的摘要为准。

承担的代价穷举如下：

- 控制面保存可能含敏感内容的工具输入，按收件箱保留期清理。
- 超过 `S_tool_input` 的输入只呈现前缀并明示截断。
- 内容不一致时该次调用被拒绝，Agent 需重新发起调用并重新请求审批。
- 文本通道（即时通讯、Issue 评论）的审批人须在决定中附带摘要前缀，多一步操作。

## 失效条件

- Claude Code 提供不可由 Agent 改写的待审批调用内容来源时，看守进程侧的重算比对可由该来源替换。

# 外部唤醒源与外部流量由托管侧持有，Agent 自唤醒源由托管侧镜像

## 背景

Agent 可能阻塞在 LLM 响应、外部系统事件、人工审批、人类消息或定时器上。托管环境要在这些等待期间挂起沙箱，必须能观察到等待的解除：在途请求要可登记，完成事件要能在沙箱不可达时到达控制面，唤醒谓词要基于持久化事实评估。Agent 直连外部系统时，控制面看不到请求的开始与完成，沙箱挂起后也没有组件接收响应。

Agent 也会自行唤醒自己。托管的第三方 Agent（Claude Code）提供会话内定时：`CronCreate` 按 5 字段 cron 表达式安排作业，`ScheduleWakeup` 安排一次性唤醒，延迟夹在 60～3600 s；它还提供 `Monitor`、后台 Bash、后台子代理与 workflow，并可把长 MCP 调用与超时的 shell 命令自动移到后台（[REF-claude-agent-sdk-typescript](../references.md)、[REF-claude-code-env-vars](../references.md)）。这些功能在 Agent 进程内到点触发，不经过任何外部交互；后台子代理在 Claude Code 主进程内运行，进程表看不到，后台任务结束后 Claude Code 注入由任务通知开始的新回合，回合结束并不意味着 Agent 静止。沙箱在触发时刻处于挂起状态时，Agent 无法运行。Claude Code 同时提供观测这些功能的信号：`background_tasks_changed` 推送完整的存活后台任务集合，Stop hook 的输入携带会话内定时作业，工具调用的输入携带 cron 表达式、延迟与超时。

castworks 托管的是完整的第三方 Agent：Agent 的功能集合由 Agent 自身决定，托管环境在不改变 Agent 行为的前提下释放等待期间的计算资源。

沙箱内持有长期凭据与 LLM 密钥会把凭据暴露给被托管的代码；Agent 进程的任意环境变量或文件都可能被读取。外部系统的出口也需要按运行实例限制，只允许该运行实例声明的目标，并在发往目标时替换凭据占位符。

Claude Code 允许把 LLM 基地址与代理指向本地端点；平台向 Agent 提供 MCP 服务器，Agent 对平台工具的调用经该服务器转发。这为把全部外部交互收归托管侧提供接入点。

## 考虑过的选项

### 沙箱直连外部系统并注入短期凭据

采用它意味着 Agent 进程直接访问 LLM 与外部系统，托管侧只注入短期凭据，按凭据有效期限制暴露面。**被拒**：控制面看不到在途请求与完成事件，沙箱挂起后无人接收响应；等待无法归约为唤醒谓词，挂起与恢复的时机不可判定；凭据仍进入沙箱，被托管代码可读取；出口无法按运行实例限制到声明的主机。

### 混合路径：LLM 经网关、外部系统直连，或反之

采用它意味着只把一类流量收归托管侧，另一类由沙箱直连。**被拒**：两套等待与凭据模型并存，直连的那一半无法登记在途请求、无法在挂起后接收完成事件；出口策略只覆盖一半流量；同一个 Agent 的两类等待需要不同的挂起判定，唤醒谓词无法统一。

### 禁用或拦截 Agent 的会话内定时、后台任务等功能

采用它意味着以 Claude Code 的配置关闭会话内定时、后台任务与 workflow，拒绝 `CronCreate`、`ScheduleWakeup` 与 `Monitor` 等工具调用，关闭长调用自动转后台，或在挂起前终止后台作业与残留进程，使 Agent 的全部唤醒都经托管侧组件，回合边界成为 Agent 静止的时点。**被拒**：Agent 能力降级——依赖会话内定时、后台任务或 workflow 的工作方式在托管环境中不可用，或在挂起时被打断，破坏托管完整第三方 Agent 的前提；终止后台作业会丢失其运行态与结果；Claude Code 每增加一项自唤醒功能，就要追加一项禁用或拦截。

### 不镜像自唤醒源，只以探测定时器兜底

采用它意味着托管侧不跟踪 Agent 的会话内定时与工具超时，挂起期间只靠周期性探测定时器解冻，检查 Agent 是否需要运行。**被拒**：会话内定时的触发延迟取决于探测间隔，间隔短则解冻频繁、挂起收益下降，间隔长则定时迟到；销毁之后沙箱内没有 Agent 进程，探测无法使会话内定时触发，Agent 在定时到点时得不到运行。

### 外部交互经托管侧，Agent 自唤醒源由托管侧观测并镜像

采用它意味着 LLM 请求经沙箱内本地代理转发到 LLM 网关，外部系统流量经本地代理或透明拦截器转发到出口代理；控制面拥有订阅、webhook、状态式轮询、人类通道与定时器；冻结期间 Agent 持有的连接上到达的入站数据由看守进程上报；沙箱内只有看守进程持有的运行实例令牌，Agent 进程不持有令牌；出口代理按运行实例落地允许主机与凭据占位符替换。Agent 的会话内定时、`sleep` 进程、工具超时与 `Monitor` 截止照常由 Agent 自行触发，Agent 驱动器与看守进程从工具调用、hook 输入、后台任务集合与进程表观测其触发时刻，控制面把它镜像进唤醒集合，保证到点时 Agent 进程可运行；后台任务照常运行。**采用**——见决策。

## 决策

采用外部唤醒源与外部流量由托管侧持有、Agent 自唤醒源由 Agent 触发并由托管侧观测与镜像。

外部唤醒源与外部流量：Agent 的每一次可能阻塞的对外交互都经过本地代理、透明拦截器、LLM 网关、连接器或 Agent 驱动器之一；LLM 请求经本地代理转发到 LLM 网关，外部系统流量经本地代理或透明拦截器转发到出口代理，通道按主机选择（[ADR-platform-does-not-execute-external-operations](adr-platform-does-not-execute-external-operations.md)）；沙箱内不持有长期凭据与 LLM 密钥，Agent 进程不持有运行实例令牌；出口策略按运行实例限制允许主机，并在出口代理替换凭据占位符（I1、I6）。

Agent 自唤醒源：会话内定时、`sleep` 进程、工具超时与 `Monitor` 截止由 Agent 自行触发，托管侧观测其触发时刻并镜像进唤醒集合，保证到点时 Agent 进程可运行；托管侧不以禁用、拦截或终止 Agent 的功能换取可挂起性（I1）。以挂起为目的的销毁路径上，看守进程在 Agent 正常退出之后终止已声明的第三方 MCP 服务器（含其子进程），这是挂起路径中唯一终止的进程；除此之外，任何挂起路径都不终止进程。

## 后果

本决策使项目承担以下义务（穷举）：

- Agent 的对外交互必须经过本地代理、透明拦截器、LLM 网关、连接器或 Agent 驱动器之一；直连外部系统不在支持范围内。第三方工具调用经本地代理或透明拦截器到出口代理，它是运行中的工具，不是可挂起的阻塞条件；长等待由 Agent 转为订阅并结束回合。
- 沙箱内不存放长期凭据与 LLM 密钥；运行实例令牌只由看守进程持有，按控制面的 `TokenRotate` 轮换，Agent 进程的环境变量与文件中不出现令牌。
- 出口代理默认拒绝全部主机，只按运行实例的出口策略放行；出口策略由连接器生成，由沙箱提供者落地，未列入的主机拒绝而不是黑洞。
- 凭据以占位符形式进入沙箱，出口代理在发往允许主机时替换；需要本地签名或非请求头认证的客户端不受支持。
- 订阅、webhook、状态式轮询、人类通道与定时器由托管侧拥有；它们的完成事件必须送达控制面，不得依赖沙箱在挂起期间接收；完成事件的持久化、去重与等待判定按 [ADR-wait-on-durable-inbox](adr-wait-on-durable-inbox.md) 处置。
- 冻结期间 Agent 持有的非 LLM 上游连接收到载荷字节时，看守进程必须上报，使冻结中的运行实例恢复。
- Agent 必须被配置为使用本地代理与平台 MCP 服务器；非必要的启动期外联关闭，本地代理与透明拦截器对未放行目标立即拒绝。
- 沙箱提供者必须支持按运行实例落地出口策略：k8s 路径为平台出口代理加 NetworkPolicy，平台出口代理逐请求校验运行实例令牌中的代，不使用缓存；Substrate 路径为以运行实例与代为键的 EgressPolicy，在为该代预配沙箱时按代落地，快照恢复沿用同代副本，在本代沙箱作废、提供者确认、进入降级、放弃、显式结束与代递增时撤销对应代的策略，撤销之后拒绝该代的落地与更新。
- Agent 驱动器必须从 Agent 的工具调用、hook 输入与消息中观测会话内定时、工具超时与 `Monitor` 截止，看守进程必须从进程表识别到期时刻已知的定时睡眠，两者以集合上报触发时刻，触发时刻无法确定的条目同样上报；控制面必须在挂起期间按这些触发时刻提前恢复运行实例，Agent 进程未运行时以恢复句柄启动它而不写入输入，由 Agent 自行恢复并触发会话内定时。
- 托管侧不设置关闭会话内定时、后台任务、workflow 或长调用自动转后台的配置，不拒绝对应的工具调用；后台作业以 Agent 自身报告的后台任务集合为准，进程表只补充不属于任何任务的残留进程。
- 挂起路径中看守进程唯一终止的进程，是以挂起为目的的销毁路径上 Agent 正常退出之后的已声明第三方 MCP 服务器（含其子进程）：这些服务器是 Agent 按声明启动的子进程，Agent 退出后没有客户端，销毁重建后随新的 Agent 进程重新启动，终止它们不损失 Agent 能力。后台作业、残留进程与孤儿进程在任何挂起路径中都不终止，所选挂起路径要求它们不存在时看守进程回 `Busy`。
- 后台作业存活或回合中多个 Agent 循环并发时，冻结只依据静止证据（没有任何 Agent 循环能在不依赖托管侧唤醒的情况下推进）执行，并登记探测定时器；后台作业存活或存在不随续接恢复的自唤醒条目时，不以挂起为目的销毁。

承担的代价穷举如下：

- 全部流量多一跳；本地代理要处理流式响应、在冻结期间持有上游连接；LLM 网关的在途请求与回放存储成本见 [ADR-two-tier-llm-proxy](adr-two-tier-llm-proxy.md)。
- 托管侧成为全部外部交互的故障域；LLM 网关、连接器或出口代理不可用时，Agent 的对应操作被阻塞或失败。
- 沙箱不能运行依赖直连网络或本地签名的客户端；这类能力不受支持。
- 出口策略的占位符替换只覆盖请求头；其他认证方式不受支持。
- 每接入一个外部系统都要配置出口策略与凭据注入；默认拒绝会使未配置的集成直接失败。
- 后台作业存活，或自唤醒条目不随续接恢复时，运行实例只能冻结、不能销毁；冻结不释放内存，资源节省减少；不具备冻结能力的沙箱提供者（Substrate 提供者）在后台作业存活期间不挂起。
- 镜像依赖 Claude Code 的工具、hook 与消息契约，Claude Code 版本变化时观测逻辑须随之调整；契约未覆盖的进程内定时器不被镜像，其触发可能延迟到探测定时器到期。
- 触发时刻无法确定的自唤醒条目（例如无法解析的 cron 表达式）存在期间，运行实例不挂起。
- 静止冻结依赖活动度观测，判据误差表现为少冻结，或 Agent 的推进被延迟到探测定时器到期。
- 看守进程不终止 TLS，无法区分保活帧与业务数据，入站数据引起的误唤醒按普通唤醒处理，增加解冻次数。

## 失效条件

- Agent 运行平台提供可信的沙箱内边车，能上报全部阻塞交互并在挂起期间独立存活，且凭据可按请求委派、沙箱内不出现长期密钥时，托管侧不必拥有全部流量。
- 外部系统都支持向控制面推送完成事件并按运行实例签发短期凭据，直连不再丢失唤醒源时，本决策的收归范围可以缩小。
- Claude Code 的消息、hook 输入与工具调用不提供后台任务集合与会话内定时作业，自唤醒源无法从沙箱外观测时，镜像不可行，本决策的自唤醒部分失效。

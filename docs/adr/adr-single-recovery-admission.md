# 控制面发起的恢复经恢复准入放行

## 背景

挂起释放沙箱后，恢复可能由人类消息、审批、LLM 完成、外部事件、定时器、实时接入或预测性恢复触发。唤醒是突发的：节点故障会使大量运行实例同时进入重建，定时器可能同时到期，实时接入的优先级高于后台事件。恢复机制的成本不同：解冻是毫秒级，快照恢复是秒级，预热池认领与共享文件系统下的冷启动重建是十秒级，块存储下的冷启动重建是一分钟级；提供者的并发容量与预热池容量有限。

如果唤醒即刻恢复，恢复风暴会耗尽提供者容量，低优先级请求挤占人类交互；如果只用一个 FIFO 队列，无法按机制成本限速，也无法为实时接入与人类回复保留容量。恢复还必须覆盖全部重建路径，包括沙箱丢失后的重建与降级兜底，否则绕过限速的路径会重新引入风暴。

## 考虑过的选项

### 唤醒即刻恢复

采用它意味着 `wake_queued` 直接进入恢复，不经过排队与限速。**被拒**：节点故障或定时器同时到期会造成恢复风暴；低优先级请求挤占实时接入与人类回复；提供者的并发上限与预热池容量被瞬时打满；恢复失败与重试相互放大。

### 单一 FIFO 队列

采用它意味着全部唤醒进入一个先进先出的队列，按到达顺序放行。**被拒**：无法按机制成本限速，解冻与冷启动共享同一速率；无法为预热池与实时接入保留容量；优先级倒置无法修正，排队时长超过老化阈值的请求无法提升。

### 按运行实例预留容量

采用它意味着每个运行实例在唤醒前预留恢复容量，恢复时使用自己的预留。**被拒**：容量碎片化，空闲预留无法复用；冷启动并发仍不可控；预留需要在运行实例整个生命周期内维持，成本高于按需放行。

### 恢复准入作为唯一放行入口

采用它意味着所有从 `wake_queued` 到 `resuming` 的转移都经恢复准入；准入按机制独立限速、按唤醒原因优先级与老化放行、按机制占用槽位，冻结态另有截止强制放行；重建类模式与降级兜底同样经准入。**采用**——见决策。

## 决策

采用恢复准入作为控制面发起的恢复的唯一放行入口：`wake_queued` 到 `resuming` 只能经恢复准入；按机制独立限速、按唤醒原因优先级与老化放行、按机制占用槽位，冻结态另有截止强制放行；重建类模式与降级兜底同样经准入。由提供者侧直接恢复、经同代 `Hello` 回到 `active` 的带外恢复不经准入，不在本决策范围内。

## 后果

本决策使项目承担以下义务（穷举）：

- 所有从 `wake_queued` 到 `resuming` 的转移必须经准入放行，包括解冻、快照恢复、预热池认领、冷启动重建与降级兜底。
- `resume_mode` 必须在入队时确定并落库；放行时校验回调携带的机制与当前 `resume_mode` 一致，不一致时重新入队，不得放行。
- 并发型限额必须按机制占用槽位，槽位带到期时间；到期未释放的槽位视为已释放，重驱动前必须重新取得槽位。
- 冻结态的入队必须携带冻结上限截止；截止到达仍未放行时，所有者必须直接放行并计入超限，不得让冻结超过上限。
- `admit` 对同一运行实例幂等，不得重置老化；队列随所有权转移按 [ADR-single-writer-per-run](adr-single-writer-per-run.md) 的义务从 `run` 行重建。
- 唤醒原因优先级、老化阈值、各机制限速值、各机制并发上限与预热池保留比例必须由 `suspendpolicy` 定义，`runcontroller` 只提供状态、槽位计数与调用点。

承担的代价穷举如下：

- 低优先级恢复多一段排队时延；优先级与老化参数的取值直接影响尾延迟。
- 跨副本的并发限额是近似值，同时放行时可能短暂超出上限。
- 槽位租约与到期回收增加状态与对账路径。
- 准入队列是所有者副本内存中的缓存，`suspendpolicy` 是链入 `runcontroller` 的库：某个副本的准入队列或 `suspendpolicy` 调用异常，会阻塞该副本所持运行实例的经准入恢复（同一库缺陷随构建波及全部副本），带外恢复不经准入；故障由截止放行、对账兜底与接管后按 `run` 行重建准入队列收敛。
- 队列在易主后重建，重建期间队列条目的相对顺序可能变化。

## 失效条件

- 快照恢复、预热池认领与冷启动重建的恢复时延都达到解冻路径的时延目标，且提供者的并发上限与预热池容量在唤醒突发下不再限制同时恢复的运行实例数时，唤醒即刻恢复不再造成恢复风暴。
- 沙箱提供者提供原生的全局准入与优先级调度，控制面不再需要自己的准入队列。
- 按到达顺序放行时，实时接入与人类回复的恢复在节点故障或定时器同时到期引起的唤醒突发下仍满足恢复时延目标，单一 FIFO 队列可以替代按唤醒原因优先级与老化的放行。

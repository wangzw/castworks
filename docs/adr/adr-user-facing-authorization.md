# humanchannel 作为唯一面向用户的入口执行用户授权

## 背景

创建、结束、查询与兜底[运行实例](../glossary.md)，读取[工作区](../glossary.md)文件，接入终端，发送消息与提交审批决定，都是由人类用户发起的操作。平台部署服务于一个组织内的多个项目，这些操作只有在核对发起用户及其项目权限之后才能执行，否则任一能发起请求的用户都可以跨项目读取工作区、终止或兜底他人的运行实例。`runcontroller` 是运行实例状态机，`workspace` 是基础层模块，两者都不对接身份提供方，也不掌握项目成员关系；顶层模块中没有对外的授权层。[人类通道](../glossary.md)（`humanchannel`）校验消息、审批与[实时接入](../glossary.md)的用户与通道绑定。

终端（`/terminal`）与[沙箱](../glossary.md)外文件读取（`/files`）经入站路由到达[看守进程](../glossary.md)。入站路由到看守进程这一跳没有认证，也不向看守进程传递用户身份；同节点或同一 Pod 内的进程可以直接连到看守进程的入站端口。

即时通讯与 Issue 评论等外部通道中，外部账号与平台用户之间没有天然的对应关系。沙箱内的 Agent 可以经[出口代理](../glossary.md)以注入的项目凭据调用外部系统，在已绑定运行实例的 Issue 线程中以项目凭据的身份发表评论；通道只按线程绑定运行实例时，这样的评论会被当作人类的消息或审批决定。

## 考虑过的选项

### 设立顶层 API 网关模块

采用它意味着设立一个顶层模块，承担身份提供方集成、项目成员判定以及向 `runcontroller`、`workspace` 的转发。**否决**：多出一个模块与一套部署；用户、项目与通道逻辑在网关与 `humanchannel` 之间重复，两处的判定可能不一致。

### runcontroller 与 workspace 各自校验用户

采用它意味着两个模块各自对接身份提供方并判定项目成员资格。**否决**：项目成员逻辑与身份提供方依赖分散到状态机与基础层模块，违反模块依赖方向；两处判定须同步演进。

### 以通道绑定代替成员资格与审批权校验

采用它意味着外部通道中的线程绑定到运行实例之后，线程中的任何评论都按人类消息或审批决定处理。**否决**：通道绑定只证明线程对应哪个运行实例，不证明评论者有权；Agent 能以项目凭据在已绑定的线程中发表批准意见。

### 入站端点信任路由器转发的身份头

采用它意味着入站路由在请求头中携带用户身份，看守进程据此授权终端与文件访问。**否决**：路由器到看守进程这一跳没有认证，能直接到达看守进程入站端口的进程可以伪造身份头。

### 审批决定一律要求附加因子

采用它意味着每个审批决定都附带 Agent 取不到的因子，例如界面确认、带签名的交互回调或带外一次性审批码。**未采纳**：部分通道（Issue 评论）不支持交互回调，每次审批增加交互成本；[外部身份关联](../glossary.md)、[审批人](../glossary.md)限定与[凭据主体](../glossary.md)排除已阻止 Agent 以项目凭据冒充审批人。保留为部署可选加固。

### 文件读取的接入票据同样一次性

采用它意味着 `file` 通道与 `terminal` 通道一样，每张票据只接受一次，每个只读文件请求各申请一张。**否决**：文件 API 的列表、读取、下载与流式读取各是一个请求，界面浏览一次工作区就要为每个请求经 `humanchannel` 向 `secrets` 申请一次签发，`secrets` 进入每个只读文件请求的关键路径。

### humanchannel 作为唯一面向用户的入口，终端与文件访问以接入票据端到端认证

采用它意味着平台界面与外部通道的用户操作都经 `humanchannel` 认证与授权，`humanchannel` 以自身工作负载身份调用下游并传递已认证的用户；终端与文件访问携带 `secrets` 签发、看守进程校验的[接入票据](../glossary.md)。**采纳**，见决策。

## 决策

采用 `humanchannel` 作为唯一面向用户的入口执行用户授权：

- 平台界面只调用 `humanchannel` 的 `UserService`；用户以部署对接的身份提供方（OIDC）认证。
- [项目角色](../glossary.md)闭集为 `member`、`approver` 与 `admin`，由身份提供方的组声明经部署配置映射得到；各操作要求的角色（权限矩阵）由架构文档给出。
- `humanchannel` 以自身 SPIFFE 身份（[REF-spiffe](../references.md)）调用 `runcontroller` 与 `workspace`，并在请求中传递已认证的用户；下游不判定项目成员资格，只记录传入的用户并写审计；运行实例记录[运行实例创建者](../glossary.md)。
- 即时通讯与 Issue 评论的外部账号必须经[外部身份关联](../glossary.md)显式关联到平台用户；未关联的外部身份发出的消息与审批决定不产生事件。
- 审批决定只接受[审批人](../glossary.md)：运行实例创建者，或在其项目中持有 `approver` 角色的用户。
- `humanchannel` 拒绝外部账号等于本项目任一[凭据主体](../glossary.md)或本模块通道机器人的消息与审批决定。
- `/terminal` 与 `/files` 的请求携带[接入票据](../glossary.md)。票据由 `secrets` 按 `humanchannel` 的申请签发，入站路由原样转发，看守进程校验通过后才建立终端或读取文件。`terminal` 通道的票据只接受一次；`file` 通道的票据在有效期内可用于同一用户、同一运行实例、同一代的多次只读请求，`humanchannel` 在票据剩余有效期不足以完成一次请求时重新申请。
- 附加因子为部署可选加固，缺省不开启。

## 后果

本决策使项目承担以下义务，穷举如下：

- `humanchannel` 对接身份提供方，按部署配置把组声明映射为项目角色并限制角色缓存时长，维护外部身份关联。
- `secrets` 在凭据对象上维护凭据主体，并向 `humanchannel` 提供不含凭据值的查询；`secrets` 签发接入票据，其签名密钥与运行实例令牌的签名密钥分开。
- 接入票据的公钥集合随领取响应与令牌轮换下发给看守进程；看守进程校验票据的签名、运行实例、代、接入通道与有效期，`terminal` 通道的票据按 `jti` 只接受一次，`file` 通道的票据不做一次性检查；看守进程的入站服务只监听 Pod 地址，拒绝来源为回环或本 Pod 地址的连接。
- `runcontroller` 记录运行实例创建者，以及结束与兜底的发起用户。
- `workspace` 的沙箱外读取接口只接受 `humanchannel` 的调用。
- 部署为项目凭据使用独立的机器账号。

承担的代价穷举如下：

- `humanchannel` 位于全部用户操作的关键路径，其可用性决定用户操作的可用性。
- 身份提供方中的角色变更在角色缓存时长内可能尚未生效。
- 即时通讯与 Issue 用户须先完成账号关联，才能发送消息与提交审批决定。
- 项目凭据使用某审批人的个人令牌时，该审批人在对应通道的决定被拒绝。
- 每次终端接入多一次接入票据签发调用；文件读取在票据有效期内复用同一张票据，剩余有效期不足时多一次签发调用。
- `file` 通道的票据在有效期内可以重放：截获票据的一方能以票据所绑定用户的身份，对同一运行实例、同一代发起只读文件请求，直到票据过期。

## 失效条件

- 平台引入统一的 API 网关并由它承担身份提供方集成时，用户授权职责可迁移到网关。

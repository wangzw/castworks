# 等待意图只作软输入，经被动解析、等待签名与工具结果旁的提示获取

## 背景

托管侧以机械信号判定等待与静止：单一条件门控依据阻塞条件与运行中的工具，静止冻结依据活动度，冻结期间 Agent 持有的连接上到达的入站数据使运行实例恢复，`sleep` 进程与会话内定时的到期时刻镜像进唤醒集合（[ADR-host-owns-external-wake-sources](adr-host-owns-external-wake-sources.md)）。这些信号不需要 Agent 配合，足以保证当下这一次等待既不丢失唤醒，也不在 Agent 推进时挂起。

机械层判不清的是等待的性质：

- 前台 Bash 运行 `gh run watch 1234`，或以 `until gh pr view ...; do sleep 30; done` 轮询外部系统时，托管侧只看到一个运行中的工具调用，分不清它在工作还是在等待外部事件。运行实例只能在静止证据成立时冻结，每次轮询到点前都要解冻，回合不结束就不能销毁。改用 `subscribe_event` 登记同一等待并结束回合时，运行实例在回合边界可销毁重建。
- 后台作业存活时运行实例只能静止冻结；托管侧分不清后台 shell 是在跑测试、在等待外部事件，还是作为开发服务器提供服务。
- 回合结束时 Agent 是在向人提问还是已经完成任务，决定合适的宽限期与等待时长先验；回合边界信号本身不区分二者。
- 等待时长预测只有各来源的历史直方图，没有这一次等待的具体对象，也没有 Agent 自己的预期。

托管侧缺的信息是等待意图：在等什么、预计多久，以及某个进程是在工作、在等待，还是提供服务。缺的不是正确性判据，正确性已由机械层保证。

获取意图受以下约束：

- 托管侧不以降级 Agent 能力换取可挂起性（ADR-host-owns-external-wake-sources）：不拒绝、不阻断 Agent 的工具调用，不强制转后台，不终止进程。
- 前台工具运行期间，发给 Agent 的消息至少要等工具返回才能被读到；回合边界上的投递作为下一条用户消息，开始一个新回合。
- 每一次额外的模型调用都要求沙箱处于运行态，并产生 LLM 成本；挂起中的运行实例要先恢复。
- Agent 对意图的陈述无法由托管侧验证。

Claude Code 提供可用的接入点（[REF-claude-code-hooks](../references.md)）：`PreToolUse`、`PostToolUse`、`PostToolUseFailure` 与 `PostToolBatch` hook 返回的 `hookSpecificOutput.additionalContext` 出现在工具结果旁，模型在下一次模型请求时读到；`SessionStart` 与 `SubagentStart` 返回的 `additionalContext` 在会话或子代理开始时出现；`Stop` 与 `SubagentStop` 返回的 `additionalContext` 会让对话继续。`additionalContext` 上限 10000 字符。`PreToolUse` 与 `PostToolUse` 的输入含 `tool_name`、`tool_input` 与 `tool_use_id`，Bash 的 `tool_input` 含 `command`、`description`、`timeout` 与 `run_in_background`；`Stop` hook 的输入含 `last_assistant_message`。MCP 服务器在初始化时可以提供 `instructions`（[REF-mcp](../references.md)）。

## 考虑过的选项

### 定期询问 Agent

采用它意味着平台按周期或在挂起决策前向 Agent 发消息，询问它在等什么、预计多久。**否决**：最需要问的时候 Agent 读不到，前台工具运行期间发给 Agent 的消息至少要等工具返回；询问要先唤醒沙箱，并多一次模型调用；回答无法验证，不能作为安全判据。询问只能作为下一条用户消息投递，每次询问都开始一个由托管侧发起的回合，回合边界与投递游标中混入不属于任务的输入，打乱回合与投递模型。

### 平台 MCP 服务器提供意图回报工具

采用它意味着平台 MCP 服务器提供专门的工具，由 Agent 在开始等待时调用以回报意图。**否决**：每次回报多一次工具往返，即多一次模型调用；预计等待时长与原因可以作为已有等待工具的可选参数随调用携带，不需要单独的往返。

### 以 Stop hook 让对话继续，索取意图

采用它意味着回合结束时 `Stop` 或 `SubagentStop` hook 返回 `additionalContext`，让对话继续并要求 Agent 说明接下来在等什么。**否决**：强制多一轮模型调用；改变 Agent 结束回合的行为，属于介入；回合边界随之推迟，宽限期与安全点的判定一并后移。

### 以 PreToolUse 的 deny 改写等待方式

采用它意味着 `PreToolUse` hook 识别出轮询或阻塞等待的命令后返回 `deny` 或 `ask`，要求 Agent 改用 `subscribe_event` 或 `sleep_until`。**否决**：拒绝 Agent 选择的工具调用属于能力降级，违背 ADR-host-owns-external-wake-sources；命令识别误判时，正常的工具调用会被误拦。

### 意图进入挂起判据

采用它意味着被判定为等待的前台调用视为满足单一条件门控，被判定为等待的后台作业视为不阻止销毁，或意图参与静止证据与唤醒集合。**否决**：意图来自关键词、分类与 Agent 自报，三者都可能出错；错误的等待判定会让运行实例在 Agent 推进时冻结，或在后台作业存活时销毁并丢失其运行态，正确性因而依赖无法验证的输入；机械层已能兜住当下这一次等待，意图只需要改善挂起收益。

### 被动解析、等待签名、工具结果旁的情境提示与可选自报参数，意图只作软输入

采用它意味着 Agent 驱动器从已有信号（工具输入、hook 输入与本地代理观察到的连接）被动解析意图，以外部系统定义中的等待签名识别对某一事件类型的等待。平台 MCP 服务器的等待工具接受可选的预计等待时长与原因。命中签名的等待与纯定时等待在下一次 `PostToolUse` 或 `PostToolBatch` 的 `additionalContext` 中附一条可以忽略的情境提示，分别建议同类等待改用订阅与 `sleep_until`。宿主侧分类模型可选，默认关闭。意图只进入等待时长预测、宽限期选择、提示决策与指标。**采纳**，见决策。

## 决策

采用被动解析、等待签名、工具结果旁的情境提示与平台 MCP 等待工具的可选自报参数获取等待意图，等待意图只作软输入。

分工：机械层（静止冻结、入站数据唤醒与 `sleep` 到期时刻的镜像）兜住当下这一次等待；意图层改善下一次等待与等待时长预测，提示 Agent 让同类等待改用订阅，原本只能冻结的等待，其运行实例因而可以在回合边界被销毁。

边界：意图只进入等待时长预测、宽限期选择、提示决策与指标，不进入单一条件门控、静止证据、I9 与唤醒集合（I11）。平台不按周期向 Agent 提问，不以 `deny` 或 `ask` 拦截工具调用，不使用 `Stop` 与 `SubagentStop` 的 `additionalContext`，不强制转后台，不终止进程。不为获取意图额外发起 Agent 的模型调用，提示只搭载在 Agent 下一次本来就要发出的模型请求上，只在事件触发点给出，有频率上限与忽略后的退避。Agent 可以忽略。提示可以关闭，意图与提示的效果可以度量。

## 后果

本决策使项目承担以下义务：

- Claude Code 驱动器从工具输入、hook 输入与本地代理观察到的周期性连接解析意图，以 `intent_observed` 上报，每条意图带来源与置信度；控制面循环驱动器的等待由 `WaitDeclared` 显式表达，不产生意图。
- 外部系统定义声明等待签名，签名的事件类型必须属于该外部系统的事件目录；签名随沙箱侧配置下发给看守进程。
- 平台 MCP 服务器的 `instructions` 与工具描述承载同一套等待方式的选择规则；`subscribe_event`、`wait_for` 与 `sleep_until` 接受可选的预计等待时长与原因，Agent 自报与平台预测分开上报，来源不混。
- 情境提示由看守进程提供的托管 hook 二进制实现，与审批 hook 同一机制；提示内容只含事实、可选做法与可以忽略的说明，标明来自平台而非用户。
- `runcontroller` 与 `suspendpolicy` 只把意图用于等待时长预测、宽限期选择与指标；单一条件门控、静止证据、I9 前置检查与唤醒集合的计算不读取意图。
- 意图解析与上报始终开启；情境提示与宿主侧分类各有开关，默认关闭。

承担的代价：

- 情境提示只能改善下一次等待：hook 的上下文在工具结束后的下一次模型请求才可见，Agent 已在进行的轮询或阻塞等待照常继续，本次等待的挂起收益完全依赖机械层，运行实例只能冻结。
- 等待签名要按外部系统维护：外部系统的 CLI 与 API 变化时签名随之更新；没有签名的等待只做分类，不给订阅建议。
- 提示占用 Agent 的上下文与 token：每条不超过 600 字符，频率受上限与退避约束，仍计入 Agent 的上下文。
- 宿主侧分类有成本与隐私代价：命令、描述与最后一条消息发往 LLM 网关与上游 LLM，按运行实例计费；因此默认关闭。
- 依赖 Claude Code 的 hook 契约：`PostToolUse`、`PostToolBatch` 与 `SubagentStart` 的 `additionalContext` 语义、`Stop` hook 的 `last_assistant_message` 与托管策略设置的 `allowManagedHooksOnly`，在 Claude Code 版本变化时须重新核对。
- 意图会出现误判：关键词、分类与自报的误差表现为误提示与预测偏差，降低挂起收益或多占 Agent 的上下文，不影响唤醒与安全点的正确性。

## 失效条件

- 实测显示 `-p` 下 `PostToolUse` 与 `PostToolBatch` 的 `additionalContext` 不进入模型请求时，情境提示没有载体，本决策的提示部分失效。
- 提示采纳率长期过低，且提示开启与关闭的对比显示挂起收益没有改善时，情境提示的代价得不到补偿，本决策的提示部分失效。

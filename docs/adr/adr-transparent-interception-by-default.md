# Agent 出站流量默认经透明拦截，基地址与代理变量只作补充

## 背景

Agent 的 LLM 请求必须经沙箱内的本地代理到达 LLM 网关（[ADR-two-tier-llm-proxy](adr-two-tier-llm-proxy.md)），外部系统请求必须到达出口代理（[ADR-host-owns-external-wake-sources](adr-host-owns-external-wake-sources.md)）。把流量引到这两处有两类做法：修改 Agent 的配置，让它把请求发给本地端点；或者不修改配置，在沙箱内接管它发往原目的地的连接。

Agent 读到 LLM 基地址或代理变量后，其行为可能随之改变。改变的内容由 Agent 的实现决定，托管环境不能约束，也不能随 Agent 的版本逐项跟踪。Agent 进程树中的工具、脚本与 SDK 也不保证读取这些配置，不读取配置的请求到不了本地代理。

本地代理必须看到 LLM 请求的明文：`request_hash` 的计算、请求模式的选定、内容事件的缓冲、保活事件的发送与恢复后的取回都在沙箱内完成。LLM 请求以 TLS 发往 LLM 主机，接管连接的组件必须以 Agent 信任的证书终止 TLS。

沙箱内已有本地 DNS、透明拦截器与合并信任库，供 `mitm` 与 `passthrough` 网络通道使用（[ADR-platform-does-not-execute-external-operations](adr-platform-does-not-execute-external-operations.md)）。出口 CA 的私钥只在出口代理侧；Substrate 路径的出口 CA 属于 Substrate 出口网关（[REF-substrate](../references.md)），平台不持有。

## 考虑过的选项

### 以 LLM 基地址指向本地代理为默认

采用它意味着看守进程为 Agent 进程设置 LLM 基地址，Agent 以明文 HTTP 把 LLM 请求发到本地代理。**被拒**：Agent 读到非默认端点后的行为不受托管环境约束；Agent 进程树中不读取该配置的 LLM 调用到不了本地代理；不支持基地址配置的 Agent 无法托管。

### 以代理变量为默认

采用它意味着 Agent 进程树的 HTTP 客户端按 `HTTP_PROXY` 与 `HTTPS_PROXY` 把请求发到本地代理。**被拒**：Agent 同样读到代理配置；忽略代理变量的工具到不了本地代理；LLM 请求以 CONNECT 隧道到达，本地代理仍须终止 TLS 才能看到明文，代理变量不能免除证书。

### 透明拦截，LLM 主机的 TLS 在出口代理或 LLM 网关终止

采用它意味着 LLM 主机复用 `mitm` 网络通道，透明拦截器把原始 TLS 字节转给托管侧，由托管侧终止 TLS。**被拒**：沙箱内没有组件看到请求明文，本地代理无法计算 `request_hash`、选定请求模式、缓冲内容事件与发送保活事件；冻结期间停滞的客户端连接须跨越网络中间层维持，与 [ADR-two-tier-llm-proxy](adr-two-tier-llm-proxy.md) 的决策冲突。

### 透明拦截，看守进程以平台 CA 签发的叶子证书终止 TLS

采用它意味着看守进程生成密钥对，由控制面以平台 CA 为 LLM 主机签发短期叶子证书。**被拒**：Substrate 路径的出口 CA 不由平台持有，平台须另建一个全部沙箱共同信任的 CA；叶子私钥泄露后，在证书有效期内可对信任该 CA 的其他沙箱冒充 LLM 主机；另需签发接口与轮换流程。

### 透明拦截为默认，看守进程以每沙箱实例的拦截 CA 在本地终止 LLM 主机的 TLS

采用它意味着 Agent 进程保持自身的默认网络配置，本地 DNS 把 LLM 主机与外部系统主机解析到透明拦截器；LLM 主机的 TLS 由看守进程以自己生成的拦截 CA 签发的证书终止，LLM 基地址与代理变量在透明拦截不适用时显式启用。**采用**，见决策。

## 决策

采用透明拦截作为 Agent 出站流量的默认途径。Agent 进程保持自身的默认网络配置，本地 DNS 把 LLM 主机与外部系统主机解析到看守进程内的透明拦截器。LLM 主机的 TLS 由看守进程以每沙箱实例的拦截 CA 签发的证书在本地终止，明文请求进入本地代理的 LLM 请求处理；外部系统主机的 TLS 不在沙箱内终止，由出口代理按注入规则处理。LLM 基地址与代理变量只作补充，在透明拦截不适用的 Agent 或主机上显式启用。

## 后果

本决策使项目承担以下义务，穷举如下：

- 看守进程必须为每个沙箱实例生成拦截 CA，私钥只保存在看守进程的内存中，不写入文件系统，不离开沙箱；拦截 CA 只为 LLM 主机签发证书，其证书并入合并信任库。
- Agent 驱动器必须声明其 Agent 的 LLM 主机；本地 DNS 与透明拦截器对 LLM 主机的判定先于网络通道。
- 默认不得向 Agent 进程树注入 LLM 基地址与代理变量。LLM 基地址只由 Agent 驱动器的配置启用；代理变量只在运行实例的网络通道中存在 `proxy` 主机时注入。
- 代理变量启用时，以 CONNECT 到达本地代理的 LLM 主机请求必须与透明拦截的 LLM 连接按同一方式处理。
- 外部系统定义未声明网络通道时取 `mitm`。
- 出口 CA 的私钥仍只在出口代理侧；拦截 CA 不得为外部系统主机签发证书。

承担的代价穷举如下：

- 沙箱内多一处 TLS 终止，每条 LLM 连接多一次握手与加解密开销。
- 快照包含看守进程的内存，拦截 CA 的私钥随快照保存；私钥泄露后只能对信任该沙箱实例合并信任库的进程冒充 LLM 主机。
- 对 LLM 主机固定证书或不读取合并信任库的 Agent 不能使用透明拦截，只能使用 LLM 基地址，并承担读到非默认端点后的行为改变。
- 网络通道中存在 `proxy` 主机的运行实例，Agent 进程树仍读到代理变量。
- 依赖 Agent 流式看门狗取值的冻结上限须在 Agent 的默认网络配置下测定，LLM 基地址配置下的测定值不能沿用。

## 失效条件

- Agent 提供接入托管侧代理的配置方式，且该方式下的行为与默认网络配置一致时，透明拦截与拦截 CA 不再必要。
- 被托管的 Agent 普遍对 LLM 主机固定证书时，默认途径不可用，LLM 基地址成为事实上的唯一途径。

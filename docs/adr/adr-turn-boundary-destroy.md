# 以挂起为目的的销毁只在回合边界

## 背景

以挂起为目的的销毁会删除沙箱，Agent 进程的内存状态随之丢失；恢复只能依靠 Agent 自身的会话恢复机制。第三方 Agent（Claude Code）以无头模式运行，`--resume` 可以续接会话（[REF-claude-code-headless](../references.md)），但回合中的在途 LLM 流、工具调用与部分输出无法安全重放：恢复后可能重复执行有副作用的工具，也可能丢失尚未持久化的结果。

回合内的等待发生在 LLM 响应、外部系统调用、人工审批与 `sleep_until` 等场景。如果只在回合边界挂起，这些等待无法释放资源；如果在回合中销毁，恢复语义不可靠。人机交互默认是异步回合制，实时接入期间还需要保持沙箱可服务。Claude Code 的 hook 提供 `defer`、`timeout` 与 `onFailure` 控制（[REF-claude-code-hooks](../references.md)），使阻塞型审批可以推迟到回合边界。

## 考虑过的选项

### 回合中销毁并合成中断消息

采用它意味着回合进行中也可以销毁沙箱，恢复后由控制面向 Agent 投递一条「回合被中断」的通知，由 Agent 续接会话。**被拒**：在途 LLM 流、工具调用与部分输出无法安全重放；恢复后可能重复执行工具或丢失结果；中断续接只能作为降级路径，不能作为常规挂起机制。

### 回合中无限期冻结

采用它意味着回合中的等待一律冻结沙箱，不设冻结上限，也不升级到快照或销毁。**被拒**：内存不释放，长期等待会占住内存；冻结上限与节点内存压力最终要求升级到快照或销毁；没有上限时，节点无法回收被冻结运行实例占用的内存。

### 只做销毁重建，不做冻结与快照

采用它意味着所有挂起都以销毁重建实现，不实现冻结与快照。**被拒**：短等待也要付出重建时延；回合中的等待无法释放内存；实时接入期间无法保持沙箱可服务；对 L1 与 L2 的回合内等待没有可用的挂起机制。

### 只在回合边界销毁，回合中冻结或快照

采用它意味着以挂起为目的的销毁只在 I9 安全点执行；以挂起为目的的 L1 与 L2 销毁只在回合边界，L0 不以挂起为目的销毁；回合内可转换的等待经 `subscribe_event` 转为订阅、经定时转为运行实例范围等待、经 hook 的 `defer` 推迟审批，转为回合边界；回合中只允许冻结或快照。**采用**——见决策。

## 决策

采用以挂起为目的的销毁只在回合边界：以挂起为目的的销毁只在 I9 安全点执行；以挂起为目的的 L1 与 L2 销毁只在回合边界，L0 不以挂起为目的销毁；回合内可转换的等待经 `subscribe_event` 转为订阅、经定时转为运行实例范围等待、经 hook 的 `defer` 推迟审批，转为回合边界；回合中只允许冻结或快照。显式结束、进入 `Degraded`、放弃、本代沙箱作废与 `fence_and_bump` 对旧代的销毁等不以挂起为目的的销毁不受此限。

## 后果

本决策使项目承担以下义务（穷举）：

- 以挂起为目的的销毁必须同时满足 I9：Agent 进程正常退出、无在途请求、无其他进程、工作区已持久化、恢复句柄已落库。
- 以挂起为目的的 L1 与 L2 销毁只能发生在回合边界；回合中的等待只允许冻结或快照。显式结束、进入 `Degraded`、放弃、本代沙箱作废与 `fence_and_bump` 对旧代的销毁等不以挂起为目的的销毁不受此限。
- L0 没有回合信号，不得以挂起为目的销毁；显式结束与失败路径不受此限。
- 可转换的等待必须能转为回合边界：`wait_for` 经 `subscribe_event` 转为订阅，阻塞型定时经定时转为运行实例范围等待，阻塞型审批经 hook 的 `defer` 推迟；`request`（平台 MCP 服务器代理的同步连接器操作）不能转换，解冻后回到 `BlockedOn`，完成后由平台 MCP 服务器直接返回。
- 冻结达到上限时，冻结上限处置在 `DRAIN` 与 `SNAPSHOT` 两个分支中择一。选定 `DRAIN` 时，本地代理回放跑完本次 LLM 请求，hook 以「批准后以消息通知」拒绝，平台 MCP 工具返回等待已转为订阅或定时的结果，使回合能够结束；运行实例进入 `Draining`，`turn_ended` 之后经「排空完成」进入销毁，销毁在 I9 预检通过时发生。选定 `SNAPSHOT` 时执行冻结中升级，不进入 `Draining`，也不经此路径销毁。`request` 不进入 `Draining`，解冻后回到 `BlockedOn`，此后不再冻结。
- 实时接入期间只冻结、不销毁；实时接入的各通道中，只有终端或文件通道的接入会中止已开始的快照或销毁尝试，平台界面会话的接入不中止进行中的挂起尝试。

承担的代价穷举如下：

- 回合中的长等待在边界之前仍占住沙箱，内存不能立即释放。
- 要求 Agent 有明确的回合模型与「结束回合再等待」的表达方式；不支持该模型的 Agent 只能停留在 L0 或 L1 的受限机制。
- 订阅、定时与 `defer` 是可转换等待都要实现的翻译，Agent 与平台 MCP 服务器的契约更复杂。
- `request` 超过冻结上限后仍占用沙箱，直到同步连接器操作完成。
- 边界销毁的重建时延高于冻结；对短等待仍可能选择冻结而不是销毁。
- 实时接入期间只能冻结，无法释放内存。

## 失效条件

- Agent 支持回合中持久化检查点，且所有在途工具调用都能幂等重放。
- 冻结的成本降到可以无限期保持，内存压力不再要求升级到快照或销毁。

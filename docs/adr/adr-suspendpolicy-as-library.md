# 挂起与恢复策略以进程内库调用

## 背景

挂起决策必须在 `run` 行锁内完成：唤醒谓词为真时不得挂起（I3），谓词与决策之间不能插入事件。策略还需要每运行实例的自适应状态：抖动预算、探测退避、`Busy`、无应答与提供者失败次数、已做预测性恢复的 `request_id`。恢复准入队列与按机制的并发限额也由策略持有，但它们的持久事实在 `run` 行上。

如果把策略做成独立服务，在行锁内调用会把锁持有时间与可用性交给另一个进程；在行锁外两阶段调用则在决策与提交之间留下事件到达的窗口，违反 I3、I5。策略还必须符合模块依赖方向：它不能读取 `runcontroller` 的表，也不能调用沙箱提供者。

## 考虑过的选项

### 独立策略服务，在行锁内调用

采用它意味着 `runcontroller` 在持有 `run` 行锁时通过远程调用请求策略决策，拿到结果后在同一事务内提交转移。**被拒**：网络调用进入数据库事务与行锁，锁持有时间与失败率由策略服务决定；策略服务不可用时该运行实例无法做任何挂起决策；决策不再与状态读取原子。

### 独立策略服务，在行锁外两阶段调用

采用它意味着 `runcontroller` 先读取状态并调用策略，再在后续事务中提交转移与决策结果。**被拒**：决策与提交之间事件可以到达，谓词可能已经为真，挂起仍然会发生；需要再校验、重试与回滚，复杂度又回到 `runcontroller`；两次调用之间的状态版本必须额外校验。

### 策略代码并入 `runcontroller`

采用它意味着挂起策略的函数、参数与状态直接写在 `runcontroller` 的代码与表结构中。**被拒**：策略与机制混在一起，策略与机制的演进节奏不同；策略无法独立测试与替换；模块边界消失，策略参数与实验性调整都要改动状态机代码。

### 独立模块以进程内库调用

采用它意味着 `suspendpolicy` 作为独立模块编译成库，链接进 `runcontroller` 进程；策略在行锁内同步调用，不读写数据库，每运行实例的策略状态存于 `run.policy_state`，准入队列是内存缓存，槽位计数经注入接口取得。**采用**：见决策。

## 决策

采用 `suspendpolicy` 作为链接进 `runcontroller` 进程的库。挂起决策、冻结中复评、机制选择与槽位重新取得在 `run` 行锁内同步调用；准入排队估计由策略函数提供，按 `run` 行计算，不读所有者副本的准入队列；`admit`、`release` 与其他只修改进程内队列的调用在事务提交后执行。策略不读写数据库，每运行实例的策略状态存于 `run.policy_state`；准入队列是内存缓存，槽位计数经注入接口取得，依赖方向保持为 `runcontroller` 依赖 `suspendpolicy`。

## 后果

本决策使项目承担以下义务，穷举如下：

- 在 `run` 行锁内调用的决策与估计函数（`decide`、`review`、`mechanism`、`on_resumed` 与各估计函数）必须只依赖调用方传入的上下文与 `policy_state`，不得直接访问数据库、外部服务或沙箱提供者。`pick_for_pressure` 由副本在节点压力复评时于行锁外批量调用，候选集由调用方只读列出，同样只依赖传入的上下文。策略产生的抖动与退避取值随决策结果落库，重驱动不得重新抽样。
- `admit`、`release` 与 `reacquire_slot` 是有状态的队列与槽位操作，不在上述纯函数约束之内：`admit`、`release` 依赖进程内队列，在事务提交后调用；`reacquire_slot` 在行锁内依赖注入的槽位计数接口。槽位计数只经该接口取得，接口由 `runcontroller` 实现并查询 `run` 表，`suspendpolicy` 自身仍不直接查询 `run` 表。
- 每运行实例的全部自适应状态必须能序列化进 `run.policy_state`，并在所有权转移后从该列恢复。
- 准入队列随策略驻留进程内；重建义务归 [ADR-single-writer-per-run](adr-single-writer-per-run.md)，本记录不重复字段细节。
- 策略参数的默认值、归属与版本必须明确；策略行为变化不得要求改变 `runcontroller` 的状态机。

承担的代价穷举如下：

- 策略与 `runcontroller` 共享进程故障域与发布节奏，策略缺陷会影响控制面。
- 策略不能独立扩缩容，也不能独立于 `runcontroller` 部署。
- 行锁内的策略计算计入每次挂起决策与复评的时延；策略复杂度受锁持有时间约束。
- 策略只能用调用方传入的上下文，节点压力等外部信息必须由 `runcontroller` 预先查询并传入。

## 失效条件

- 行锁不再是决策的串行化点，或数据库支持在锁内安全调用外部服务。
- 策略需要独立于运行实例状态的持久存储或独立扩缩容，进程内库无法满足。
- 策略计算时间持续超出锁持有预算，且无法通过拆分上下文或缓存缩短。

# 按代拒绝旧沙箱的消息与副作用

## 背景

运行实例的生命周期跨越沙箱的创建与销毁，每次为运行实例预配新沙箱都使它改由另一个沙箱实例承载，例如销毁重建与沙箱丢失后的重建；快照恢复沿用同一沙箱实例，不替换沙箱。被替换的沙箱在替换之后可能仍然存活，并继续发送协议消息、持有运行实例令牌、经出口代理写入外部系统、写入工作区或推进投递游标；控制面判定沙箱丢失而沙箱实际仍在运行时（例如控制面与沙箱之间的网络分区），同样出现这一情形。

控制面数据库是运行实例状态的唯一事实源，消息、令牌、工作区写入与游标推进是否被接受，必须能由控制面依据自身持久化的状态判定。运行实例令牌由 LLM 网关与连接器校验，看守进程以它认证出站流上的首个 `Hello`。沙箱发往外部系统的请求经出口代理替换凭据占位符后放行，出口代理只要仍为某个沙箱放行，该沙箱就能以真实凭据写入外部系统。投递语义为至少一次；看守进程在出站流重连后重放控制面尚未提交的消息，重放的消息可能在其发送方被替换之后才到达，接收方必须能判别它是否来自被替换的沙箱。工作区在沙箱销毁与重建之间保留，共享文件系统下旧沙箱的写入对新沙箱可见，工作区的写者必须唯一。

失效判定依据因此必须由控制面分配与核验，每次预配新沙箱都取不重复且单调递增的新值，并在预配之前确定。单调使任意两值可以直接比较新旧：不向控制面查询的参与方（例如工作区租约）比较所持的代即可拒绝更旧的动作，控制面也据此按代成批作废旧代的代范围等待、代范围定时器与在途请求；运行实例范围的等待与定时器不携带代、跨代保留（[ADR-generation-scoped-waits](adr-generation-scoped-waits.md)）。快照恢复不预配新沙箱，不取新值，`sandbox_id` 与代都不变。

## 考虑过的选项

### 仅以 `sandbox_id` 区分新旧沙箱

采用该选项意味着：消息信封、令牌、工作区租约与游标推进携带 `sandbox_id`，控制面只接受 `sandbox_id` 等于当前沙箱的动作。

**否决**：`sandbox_id` 由沙箱提供者在预配或预热池认领时确定，控制面在提供者返回结果之前无从得知。工作区租约在新沙箱启动之前建立，无法携带新沙箱的 `sandbox_id`，只能在提供者返回之后补绑定；补绑定之前，租约不能区分新沙箱与仍然存活的被替换沙箱。替换前后的 `sandbox_id` 是否不同由提供者的标识规则决定，控制面无法保证。k8s 提供者以 Sandbox CR 的 `spec.operatingMode` 执行销毁与重建，前后两个沙箱属于同一 Sandbox CR，只有 Pod 被替换（[REF-agent-sandbox](../references.md)）。以 Sandbox CR 标识沙箱时，新旧沙箱的标识相同，等值比较会放行被替换的沙箱。`sandbox_id` 之间也没有先后顺序，不向控制面查询的参与方无法据它判断两个沙箱孰新孰旧。

### 依赖沙箱提供者的删除确认作为唯一失效判定依据

采用该选项意味着：控制面只在沙箱提供者确认旧沙箱已删除或已挂起之后放行新沙箱的动作，在此之前旧沙箱的动作照常接受；消息、令牌、工作区写入与游标推进的接受都以该确认为准。k8s 提供者的确认是 Sandbox CR 完成 Pod 删除，Substrate 提供者的确认是 actor 挂起完成（[REF-substrate](../references.md)）。

**否决**：删除确认在旧沙箱停止运行之后才到达，失效判定却必须在旧沙箱仍然存活时生效。控制面决定放弃一个仍在运行的沙箱时（例如判定沙箱丢失、进入 `Degraded`），旧沙箱在删除确认之前发出的消息来自尚未被删除的沙箱，所持令牌仍能在 LLM 网关与连接器上换取凭据并执行外部副作用。该选项不能把这些动作判为过期。控制面与沙箱提供者之间的网络分区使删除无法执行、确认不可得，这一窗口随之没有上界。删除确认还是运行实例级的一次性事实，不随消息、令牌与租约携带，确认之后到达的在途动作若不另带标识，无法判别来自已删除的沙箱还是新沙箱。

### 以运行实例的代拒绝全部沙箱侧动作

采用该选项意味着：运行实例的代单调递增，首次预配取初始值，此后每次预配沙箱之前递增。消息信封、令牌、工作区租约、游标推进与出口路径都按 `generation` 判定，控制面拒绝与当前代不一致的动作。控制面判定本代沙箱已被删除、已丢失或进入 `Degraded` 之后，代递增之前，本代令牌失效，本代沙箱的新连接与已建立出站流上的消息被拒绝，游标不再推进，出口路径撤销对本代沙箱的放行。工作区租约的续约不感知作废判定，这一窗口内的工作区写入由新代接管工作区的前置条件隔离。

**采纳**，见决策。

## 决策

采用运行实例的代作为统一失效判定依据：代单调递增，首次预配取初始值，此后每次预配沙箱之前递增。消息信封、令牌、工作区租约、游标推进与出口路径都按代校验，与当前代不一致的动作被拒绝。本代沙箱被判定已删除、已丢失或进入 `Degraded` 之后，代递增之前，本代令牌失效，本代沙箱的新连接与已建立出站流上的消息被拒绝，游标不再推进，出口路径撤销对本代沙箱的放行。工作区租约的续约不感知作废判定，这一窗口内的工作区写入由新代接管工作区的前置条件隔离。

## 后果

本决策使项目承担以下义务，穷举如下：

- 消息信封、令牌、工作区租约、游标推进与出口路径必须携带并校验 `generation`；上述任一项遗漏代判定即构成失效判定缺口。
- 为运行实例预配新沙箱之前，该沙箱所属的代必须已经提交；首次预配之外的每次预配都使用递增后的新代，例如销毁重建、沙箱丢失后的重建与预配明确失败后的重新预配。
- 令牌有效的条件必须包含：令牌中的代等于运行实例当前代，运行实例未进入终态，且本代未被判定作废。旧代令牌的失效由代递增、作废判定与进入终态的提交本身完成；有外部副作用的操作不得以缓存的代校验令牌。
- 出口路径必须拒绝作废代、已进入终态与旧代的请求。能逐请求向控制面查询的出口代理（例如 k8s 提供者路径的平台出口代理）按令牌有效的条件逐请求校验，不使用缓存。只按下发策略放行的出口网关（例如 Substrate 提供者路径的出口网关）必须在本代被判定作废、运行实例进入终态与代递增时撤销对应代的放行，且撤销之后到达的策略推送不得恢复该代的放行。
- 旧代沙箱发出的 `Hello` 与已建立出站流上的旧代消息都必须得到失效应答；收到失效应答的看守进程停止投递与副作用，终止 Agent 进程树后退出（[ADR-unrecoverable-stream-failure-rebuilds-sandbox](adr-unrecoverable-stream-failure-rebuilds-sandbox.md)）。
- 失效应答（`Fenced`，握手期间为 `HelloAck.fenced`）携带当前代与原因。原因是闭集：`generation` 表示代已过期；`lease` 表示同一代内工作区租约的标识、持有者或到期时刻与登记不符；`sandbox` 表示同一代内 `sandbox_id` 与登记不符。原因为 `lease` 或 `sandbox` 时，携带的当前代等于看守进程自己的代。
- 新代接管工作区仍以旧租约到期或沙箱提供者确认旧沙箱删除为前提，删除确认须携带被删除沙箱所属的代，且该代等于工作区租约所属的代。失效判定不替代该前提。删除确认之所以能作为前提，依赖于整代销毁之后提供者拒绝该代的预配、预热池认领与快照恢复，使该代不再出现沙箱实例。本代被判定作废之后、代递增之前，工作区租约的续约不感知作废判定，本代沙箱在这一窗口内的工作区写入只由该前提与新代隔离。
- 沙箱提供者的整代销毁与单个销毁必须携带代，只作用于该代的沙箱实例，不作用于更新的代；迟到执行的旧代销毁不得删除新代沙箱。整代销毁之后，提供者必须拒绝该代及更早代的预配、预热池认领与快照恢复；迟到到达的这类请求不得在删除确认之后使该代再出现沙箱实例。
- 旧代拒绝必须与消息丢失可区分，否则过期动作被拒会表现为静默丢弃；旧代拒绝也必须与依赖暂不可用导致的可重试拒绝可区分，否则仍属当前代的沙箱会因暂时故障被终止。

承担的代价穷举如下：

- 同一代内的沙箱实例携带相同的 `generation`，代判定不能区分它们。每代只有一个沙箱实例，这一点依赖预配、预热池认领与快照恢复按 `(run_id, generation, attempt_id)` 幂等，以及快照恢复沿用同一沙箱实例。提供者违背该幂等、在同一代内产生第二个实例时，两者由工作区租约的持有者与 `sandbox_id` 区分，与登记不符的一方收到原因为 `lease` 或 `sandbox` 的失效应答。
- 代递增前发出、递增后到达的消息一律被拒绝，只能依靠从收件箱重投、投递意图日志与新代的状态对账重新达成，产生重复投递与状态对账。
- 消息接收、令牌换取、租约续约、游标推进与 k8s 提供者路径的出口请求各自增加一次代比较与拒绝路径。
- LLM 网关、连接器与 k8s 提供者路径的平台出口代理校验令牌时必须向 `runcontroller` 取得运行实例的当前代。连接器的订阅登记与每个出口请求都取得最新值。`runcontroller` 的可用性与查询时延计入这类操作，`runcontroller` 不可用期间这类操作无法放行。
- Substrate 提供者路径的出口网关不逐请求判定代：从本代被判定作废、运行实例进入终态或代递增，到对应代出口策略的撤销生效，该代沙箱仍能经出口网关以真实凭据写入外部系统。撤销在其执行截止之前生效时，窗口不超过该截止，这一上界依赖撤销不会因迟到的策略推送而恢复。撤销在截止前未能生效时（例如 Substrate 控制面不可达），窗口延续到撤销生效或该代沙箱删除完成。
- 沙箱仍可继续服务而本代被判定作废或代递增时（例如误判沙箱丢失），该代沙箱的令牌、协议消息与出口一并失效，只能经重建恢复，代价是一次完整的沙箱重建。
- 新代接管工作区仍依赖沙箱提供者的删除确认或旧租约到期，删除确认须携带被删除沙箱所属的代，且该代等于工作区租约所属的代，失效判定没有消除重建对提供者确认的等待。

## 失效条件

- 同一运行实例在一个代内出现多个可写沙箱实例，且工作区租约无法把它们串行化时，代不能区分这些实例，失效判定依据需替换为每沙箱实例单调且控制面可核验的标识。
- 全部沙箱提供者都能在预配之前给出控制面可核验、在运行实例的生命周期内单调且不重复使用的沙箱实例标识时，以 `sandbox_id` 作失效判定依据的拒绝理由不再成立，统一失效判定依据可改用该标识。
- 同一代内同时存在来自不同 `sandbox_id` 的两条已通过 `Hello` 的出站流，或工作区租约在同一代内出现不同持有者的续约冲突，且这类情形的发生次数持续非零，表明同一代内存在多个存活的沙箱实例，仅以代比较不能拒绝其中任何一方。
- Substrate 提供者路径上撤销出口策略越过执行截止仍未生效的次数持续非零，或越过执行截止之后仍有该代请求经出口网关放行时，以撤销出口策略对出口路径作失效判定的窗口不再受执行截止约束，该路径需改为逐请求判定代。

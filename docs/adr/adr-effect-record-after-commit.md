# 外部副作用经效果记录在提交后执行

## 背景

运行实例的状态转移需要调用控制面之外的系统：沙箱提供者预配、挂起、恢复与销毁沙箱；`workspace` 建立、保持与释放租约；`secrets` 签发运行实例令牌；看守进程的出站流发送投递、挂起与恢复消息。这些调用跨越进程与网络，耗时从毫秒到分钟，可能超时、失败或返回不确定结果。

控制面数据库事务不能覆盖这些调用：在事务内调用会把行锁持有时间交给外部系统，提供者不可用会阻塞状态机，调用成功而事务回滚会留下无法撤销的副作用。副本在事务提交之后、调用之前崩溃时，副作用会丢失；调用在提供者侧成功而完成消息丢失时，状态会停在过渡态。重复调用必须不产生重复副作用。

## 考虑过的选项

### 在状态转移事务内直接调用外部依赖（含看守进程出站流）

采用它意味着状态转移与外部调用在同一段代码中完成，调用成功后才提交数据库事务。**被拒**：外部副作用不可回滚；锁持有时间由外部系统的响应时间决定；提供者不可用或超时会阻塞该运行实例的全部写入；调用成功而事务回滚时，副作用已经在外部系统生效，无法撤销。

### 提交后直接调用，不写记录

采用它意味着状态转移提交后立即调用外部系统，不保存待执行记录。**被拒**：副本在提交与调用之间崩溃即丢失副作用，没有重试依据；无法表达效果之间的依赖顺序；无法检测长期未完成的效果；无法在没有有效所有者时由其他副本接手执行。

### 两阶段提交或独立事务协调器

采用它意味着外部系统参与两阶段提交，或由独立协调器记录全局事务状态并驱动提交与回滚。**被拒**：沙箱提供者、`workspace` 与 `secrets` 不提供 prepare 语义；协调器成为新的单点与新的持久化状态；即使协调器存在，重复调用仍需要幂等键处理。

### 效果记录在提交后幂等执行

采用它意味着外部副作用在同一数据库事务内与状态转移一起写成效果记录，提交后由所有者或认领者按幂等键执行；执行前与完成事务按效果类别校验；效果之间的依赖以最早执行时刻表达。**采用**——见决策。

## 决策

采用效果记录承载外部副作用：需要跨进程调用外部系统、且在控制面崩溃或所有权变更后仍须重驱动执行的外部副作用，在同一数据库事务内与产生它的所有者事务、所有权获取事务或汇入写入一起写成效果记录（记录唯一键为 `(run_id, effect, ref)`），提交后执行外部调用，以调用参数中标识同一外部操作的值（按效果类别取 `run_id` 与代、`resume_id`、`suspend_id`、`delivery_id` 等）为外部调用的幂等键；执行前与完成事务按效果类别校验；效果之间的依赖以 `not_before` 表达。汇入事务写入的 `wake_check` 复用效果记录表，但在 `run` 行锁内分派、分派事务内置 `done`，不调用外部系统，不在本决策范围内。在既有出站流上作为入站消息应答同步发出的消息（`HelloAck`、`Fenced`，以及「销毁态连接」、终态 `Hello` 与本代作废的拒绝判定发出的 `Shutdown`）同样不写成效果记录，其重发依赖看守进程重连后重发触发消息重新生成。

## 后果

本决策使项目承担以下义务（穷举）：

- 每个需要效果记录的外部副作用必须能表达为效果闭集中的一种效果，并携带稳定的幂等标识；不能表达为效果的调用不得在转移事务内直接执行。
- 效果的执行参数与目标必须在写入时确定，执行器不得在执行时重新选择目标或参数。
- 执行前必须按效果类别校验：当前标识类比较 `delivery_id`、`suspend_id` 等当前标识；结果写回类比较 `resume_id` 与代；状态类中 `rotate_token` 另要求效果的代等于 `run.generation`；目标绑定类比较目标代与沙箱；保留执行类豁免代校验与终态校验。
- 完成事务必须在行锁内按效果类别再次校验，并把效果置 `done`；结果写回类（`provision`、`resume`）的完成事务校验失败时按原因处置：运行实例已终态、效果的代小于当前代或本代已作废时，提供者结果含 `sandbox_id` 即同一事务写该沙箱的单个 `destroy` 后置 `abandoned`；同代且未作废、仅 `resume_id` 不符时置 `done`，不写数据列，只在结果 `sandbox_id` 与 `run.sandbox_id` 都非空且不相等时另写单个 `destroy` 并告警。其余效果类别的完成语义见设计。
- 效果之间的先后依赖必须显式表达，例如重建的 `provision` 依赖旧代销毁完成或旧租约到期，`release_run` 依赖同一运行实例全部 `destroy`、`workspace_release` 与 `release_run_lease` 完成。
- 效果滞留超过截止时间时，由对账器按同一标识幂等重驱动，同一效果在每个截止周期内只重驱动一次；依赖未完成、目标流未建立，或截止取自 `transition_deadline` 且运行实例仍在对应过渡态的效果只顺延截止；`transition_deadline` 类效果的重驱动由「过渡态截止」守卫执行，其 `attempts` 由该守卫累加，本守卫不重复累加。
- 终态运行实例仍须执行保留执行类效果，不得因终态而丢弃销毁、工作区释放、运行实例资源释放、运行实例租约释放与出口策略撤销。

承担的代价穷举如下：

- 每次状态转移多一次效果记录写入，提交到执行之间有一段时延。
- 效果表随运行实例增长，需要保留期与清理规则；清理过早会丢失重驱动依据。
- 效果之间不保证完成顺序，正确性依赖按代的销毁语义与幂等键，而不是调用顺序。
- 执行器崩溃或提供者结果不确定时，状态会在过渡态停留到截止时间或对账周期。
- 保留执行类效果必须绕过代校验与终态校验，增加效果类别的实现与测试负担。

## 失效条件

- 所有外部系统都提供与数据库事务原子提交的幂等接口时，效果记录不再是必要的中间层。
- 出现无法用幂等键表达的外部副作用，且该副作用无法拆分为可重试的幂等调用时，本决策不成立。

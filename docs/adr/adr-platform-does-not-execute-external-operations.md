# 平台不执行第三方操作，只提供出口凭据替换、连接器事件日志与订阅

## 背景

Agent 通过第三方 MCP 服务器、命令行工具或直接 REST 请求操作外部系统（[REF-mcp](../references.md)）。托管环境需要让这些操作在沙箱不持有真实凭据的前提下仍然可用，并在操作产生的外部事件到达时唤醒运行实例。

平台的维护负担必须与第三方工具的数量解耦。第三方工具生态持续增长，平台无法为每个操作声明名称、参数、完成条件与关联锚；Agent 绕过平台工具直接调用第三方时，按操作登记的锚也无从产生。

同时，沙箱会在等待外部事件时挂起。外部唤醒源必须由托管侧持有：外部事件先落盘为持久事实，订阅在这份事实日志上匹配，完成事件写入收件箱并派生唤醒信号。

## 考虑过的选项

### 平台为每个第三方操作提供同步代理入口

采用它意味着平台 MCP 暴露一个通用操作工具，外部系统定义声明每个操作的元数据，平台执行调用、在操作返回时登记关联归属并按操作写入唤醒信号。**被拒**：维护负担随第三方工具与操作数量增长；Agent 用第三方 MCP 或命令行工具执行操作时平台看不到响应，锚无法登记；平台路径与第三方路径的语义不一致。

### 只提供出口代理，不提供事件订阅

采用它意味着第三方工具经出口代理执行操作，平台只做凭据替换；外部事件由 Agent 自行轮询。**被拒**：外部事件不经托管侧唤醒源到达，沙箱必须保持运行才能轮询；事件在轮询之间到达会丢失或延迟，挂起与恢复的时机不可判定。

### 平台提供网络通道、部署级共享的连接器事件日志与订阅，不执行第三方操作

采用它意味着第三方工具自己执行操作；平台只提供三条与工具无关的网络通道、连接器事件日志与订阅；凭据以占位符进入沙箱，由出口代理在允许主机上替换；订阅由 Agent 显式给出关联键，平台在本项目的事件上按 `(system, correlation)` 回溯与实时匹配。**采用**，见决策。

### 保留同步操作作为可选路径，同时提供通用订阅

采用它意味着平台维护两套语义：按操作代理与按事件订阅。**被拒**：两条路径的等待、审计与归属规则不一致；同步操作仍要求平台为每个操作维护元数据，可选路径会成为默认路径；第三方工具路径仍然无法登记锚。

## 决策

采用平台不执行第三方外部操作的方案。平台 MCP 只提供列出可订阅事件、登记订阅、阻塞等待、定时等待与附件取回；外部系统定义声明认证、允许主机及其网络通道、请求头占位符规则与事件源，含完成条件目录、关联键身份键与关联键规范化，不声明具体操作。第三方工具经 `proxy`、`mitm` 或 `passthrough` 三条与工具无关的网络通道执行操作。连接器事件日志在存储上部署级共享，每条事件按外部系统定义的[项目归属键](../glossary.md)归属项目；订阅是运行实例在本项目事件上的查询（[ADR-connector-events-project-scoped](adr-connector-events-project-scoped.md)）。凭据以占位符进入沙箱，由出口代理在允许主机上替换。

## 后果

本决策使项目承担以下义务，穷举如下：

- 新增第三方工具只改项目作用域的工具接入声明，不改平台 MCP 的工具闭集；外部系统定义不声明具体操作，第三方工具新增操作不需要修改它。
- 外部系统定义必须声明事件源、完成条件与关联键身份键。一次性订阅的关联键必须至少包含一个关联键身份键，否则拒绝登记。
- 带 webhook 事件源的外部系统定义必须声明项目归属键，订阅只匹配本项目的事件（[ADR-connector-events-project-scoped](adr-connector-events-project-scoped.md)）。
- 沙箱内提供本地 DNS 解析与透明拦截器，用于 `mitm` 与 `passthrough`；`proxy` 只依赖代理环境变量。
- 沙箱必须信任出口 CA，`mitm` 与需要注入凭据的 `proxy` 目标才能完成 TLS 终止。k8s 路径的平台 CA 经镜像预置或运行时注入信任库；Substrate 路径经 `systemInfo` 卷的 `trustBundle` 数据源运行时投射出口网关 CA，不预置进镜像。CA 轮换保留新旧 CA 同时受信的重叠期，重叠期不短于快照保留期上限。
- 出口代理必须把请求的唯一目的地限定为鉴权确定的授权主机，客户端 SNI 与内层 `Host` 必须与之一致，上游连接只按授权主机建立。
- 真实凭据只在 TLS 连接上注入；允许明文注入的主机必须在外部系统定义中以 `access.plaintext_hosts` 显式声明。
- 第三方工具自行实现重试与幂等。平台不提供按操作的幂等键，也不为第三方调用产生 `blocked_on`；长等待由 Agent 转为订阅并结束回合。
- 连接器事件日志的保留期必须覆盖工具调用返回到订阅登记的最大往返，使操作返回后、订阅登记前到达的事件仍可被回溯匹配。

承担的代价穷举如下：

- 平台级操作幂等、按操作审计与按操作授权消失。授权粒度退化为允许主机、凭据作用域与项目声明。
- 回合中冻结第三方工具等待的能力消失。第三方调用是运行中的工具，不是可挂起的阻塞条件。
- 中间人通道引入 CA 私钥、证书轮换、轮换重叠期与信任库注入的运维负担。需要凭据的证书固定目标与本地签名客户端不受支持；不需要凭据的证书固定目标只能走 `passthrough`。
- 本地 DNS 成为相关域名解析的单点。DoH 与 DoT 需要网络层额外拦截，否则可绕过本地解析。
- 连接器事件日志不按运行实例隔离而按项目隔离：同一项目内相同关联键的多个订阅都会收到事件。项目之间的隔离由事件的项目归属与订阅的项目字段保证，不依赖关联键精度。

## 失效条件

- 第三方工具生态收敛到少数平台可枚举的操作，且平台能可靠观察所有工具的执行结果时，操作代理路径的成本可能低于通用基座。
- 外部系统普遍支持平台可直接消费的持久事件推送，且不再需要回溯匹配时，连接器事件日志与订阅的复杂度可以降低。

# 运行实例令牌按受众签发并绑定沙箱实例密钥

## 背景

`runcontroller`（[出站流](../glossary.md)的 `Hello`）、[LLM 网关](../glossary.md)、[连接器](../glossary.md)、[人类通道](../glossary.md)与平台[出口代理](../glossary.md)都接受[运行实例令牌](../glossary.md)。平台出口代理部署在控制面命名空间之外，终止外部 TLS 并处理不可信的上游响应，经手每个 k8s [运行实例](../glossary.md)的令牌；人类通道接收来自互联网的即时通讯回调。令牌只标识运行实例而不标识接收方时，任一接收方被攻破，它收集到的令牌都能重放到其他接收方。例如，人类通道收集附件取回请求中的令牌后，经平台出口代理换取项目凭据的注入。

[看守进程](../glossary.md)以令牌加 `lease_id` 认证出站流，以 `lease_id` 续约[工作区租约](../glossary.md)。[快照](../glossary.md)恢复不递增[代](../glossary.md)，一代可以跨越同一[沙箱](../glossary.md)实例的多次[冻结](../glossary.md)与快照恢复；冻结或快照期间令牌会过期，恢复后的看守进程只能以过期令牌重连，`Hello` 必须接受过期令牌并下发新令牌。`lease_id` 不只由看守进程持有：它保存在引导记录中，Substrate 路径的领取响应以明文经过出口网关，快照包含的进程内存同时含令牌与 `lease_id`；`sandbox_id` 由调用方自报。接受过期令牌不限时长时，曾取得令牌与 `lease_id` 的一方可以在该代仍有效期间接管出站流、取得新令牌，并以续约维持工作区租约。这些不记名值都不能证明调用方是领取时的那个沙箱实例。

持有证明本身也会被复制：快照包含的进程内存里有看守进程最近计算的签名。快照恢复后 guest 时钟的行为按运行时不同，长时间冻结之后沙箱时钟同样可能落后，沙箱时钟与控制面时钟的偏差不能预先约束。

令牌中的代须等于当前代，本代作废后令牌失效；这一判定见 [ADR-generation-fencing](adr-generation-fencing.md)，本决策不改变它。

## 考虑过的选项

### 所有接收方共用一张令牌

采用它意味着一张令牌同时被出站流与各运行时 HTTP 接口接受，接收方只校验令牌所属的运行实例。**否决**：任一接收方被攻破，即可把收集到的令牌重放到其他服务，取得回放的模型响应与附件，并注入外部系统凭据。

### 按受众签发令牌组

采用它意味着一次签发同一运行实例、同一代、同一到期时刻、按接收方各一张的令牌，每个接收方只接受本身受众的令牌。**采纳**，见决策。

### 为每个沙箱实例签发 mTLS 客户端证书

采用它意味着看守进程以按沙箱实例签发的客户端证书认证出站流与续约。**否决**：k8s 与 Substrate 的签发链不同；Substrate 路径的连接经出口网关透传，客户端证书须端到端穿过网关；证书的签发与轮换落到每个沙箱，引导与快照恢复都要处理证书。

### 每个请求都附持有证明

采用它意味着看守进程发往任一接收方的每个请求都以实例私钥签名。**否决**：签名与校验给每个 LLM 请求与出口请求增加开销；接管风险集中在 `Hello` 与工作区租约续约，这两处的绑定已阻止只持有不记名值的一方接管出站流与工作区。

### 看守进程生成实例密钥，令牌与工作区租约绑定其公钥指纹

采用它意味着看守进程在领取之前生成[实例密钥](../glossary.md)，公钥指纹写入令牌的 `cnf.jkt` 与工作区租约，`Hello` 与 `RenewLease` 附实例私钥所作的[持有证明](../glossary.md)。**采纳**，见决策。

### `Hello` 的持有证明以签名时刻限定新鲜度

采用它意味着 `Hello` 与 `RenewLease` 一样对签名时刻签名，接收方要求签名时刻与服务端时刻相差不超过 `T_proof_skew`。**否决**：时窗内截获的证明可以原样重放到新的连接上，快照中的进程内存就是一处来源；时窗判定还使出站流的建立依赖沙箱时钟，而快照恢复与长时间冻结之后的偏差没有上界。

### `Hello` 的持有证明对控制面挑战签名，续约的持有证明对签名时刻签名

采用它意味着出站流建立后控制面先下发只能使用一次的挑战随机数，`Hello` 的持有证明对它签名，不带时窗；`RenewLease` 是没有往返的一次性调用，持有证明对签名时刻签名并按 `T_proof_skew` 判定。**采纳**，见决策。

### 过期令牌一律拒绝

采用它意味着 `Hello` 只接受未过期的令牌。**否决**：冻结与快照期间令牌必然会过期，恢复后的看守进程只能凭过期令牌重连；一律拒绝时，每次长冻结与快照恢复都只能走重建，冻结与快照失去保留进程状态的意义。

### 过期令牌不限时长接受

采用它意味着签名、代与租约校验都通过时，令牌无论过期多久都被接受。**否决**：令牌的有效期限制不了泄露令牌的可用窗口，持有旧令牌的一方可以在代有效期内的任意时刻重连。

### 接受下界随每次轮换推进到上一组令牌

采用它意味着每次轮换完成都把可接受令牌的到期时刻下界推进到上一组令牌，不论看守进程是否收到了新令牌组。**否决**：控制面发往看守进程的消息不跨连接重放，连接中断时未送达的轮换消息随之作废（[ADR-asymmetric-stream-replay](adr-asymmetric-stream-replay.md)）；轮换消息连续两次未送达，看守进程所持的令牌就落到下界之下，只能以认证失败退出并经重建恢复，Agent 进程与看守进程的内存状态随之丢失。

### 过期令牌受接受下界约束，且只在同一沙箱实例延续与快照恢复状态下接受

采用它意味着控制面记录可接受令牌的到期时刻下界，并随轮换推进这一下界，下界不越过看守进程在 `Hello` 中出示的令牌。过期令牌只在冻结、解冻与快照恢复等延续同一沙箱实例的状态下接受。**采纳**，见决策。

## 决策

采用按受众签发并绑定实例密钥的运行实例令牌：

- `secrets` 一次签发令牌组：同一运行实例、同一代、同一到期时刻、同一实例公钥指纹，按受众各一张，受众闭集为 `runcontroller`、`llmgateway`、`connectorhub`、`humanchannel` 与 `egress`；每个接收方只校验本身受众的令牌，`secrets` 按调用方身份限定可校验的受众。
- 看守进程在领取之前生成实例密钥，私钥只保存在进程内存中；领取请求体提交公钥；[引导接口](../glossary.md)经 `SetHolderKey` 在签发令牌之前把公钥指纹登记到工作区租约，令牌的 `cnf.jkt` 携带同一指纹。
- `Hello` 与 `RenewLease` 必须附持有证明；接收方核对公钥指纹与令牌、租约所登记的指纹一致，并验签。`Hello` 的持有证明对控制面为本条流生成的一次性挑战随机数签名，不带时窗，不依赖沙箱时钟；`RenewLease` 的持有证明对签名时刻签名，签名时刻与服务端时刻相差不得超过 `T_proof_skew`。
- `runcontroller` 记录本代的实例公钥指纹与令牌接受下界；到期时刻低于接受下界的令牌一律拒绝；过期令牌只在处于同一沙箱实例延续或快照恢复状态时接受，新代状态下拒绝。接受下界随轮换与被接受的 `Hello` 推进：按截止时间发起的轮换把下界推进到上一组令牌，使可接受的令牌只剩最近一张及其直接前任；`Hello` 出示的令牌早于最近签发的令牌组（上一组轮换消息未送达）时，由此发起的轮换把下界取为所出示令牌的到期时刻，不越过看守进程实际持有的令牌。

## 后果

本决策使项目承担以下义务，穷举如下：

- 领取请求体携带实例公钥；领取响应与 `TokenRotate` 承载以受众为键的令牌组，轮换不改变 `cnf.jkt`。
- `secrets` 每次签发产生按受众划分的多张签名；各接收方只按本身受众调用校验。
- `workspace` 在租约上保存实例公钥指纹，续约时核对指纹并验签；指纹只由引导接口在领取时登记，快照期间清空持有者的 `HoldLease` 不清除指纹；租约查询只向 `runcontroller` 提供（[ADR-control-plane-call-authentication](adr-control-plane-call-authentication.md)）。
- `runcontroller` 保存实例公钥指纹与令牌接受下界，轮换时以记录的指纹申请令牌，在新代进入运行、代递增与沙箱销毁确认时清空两者。
- 出站流的握手由控制面先发挑战，挑战携带随机数与服务端时刻；看守进程收到挑战后才发 `Hello`，控制面只接受对本条流所发随机数的签名，每个随机数只能使用一次。
- 看守进程以每次挑战携带的服务端时刻校时，续约所用的签名时刻取校时后的时间。`workspace` 因签名时刻越出时窗拒绝续约时返回服务端当前时刻，错误可重试，看守进程据此校时后重试：周期续约重试一次，仍被拒才按无法续约处理；首次续约连续被拒时按可重试错误退避重试，期间不建立出站流。
- 首次续约成功之后才发 `Hello`，初次领取与快照恢复都是如此：快照恢复与长时间冻结之后，看守进程先续约工作区租约，越出时窗时按上一条校时重试，续约成功、租约持有者恢复为本沙箱之后才重建出站流，收到挑战后再次校时并发出 `Hello`。首次续约以不可重试错误失败时例外：看守进程停止工作区写入、冻结 Agent 进程树后仍发出 `Hello`，由控制面的租约核对以代失效应答，看守进程随之退出。
- 实例私钥只保存在看守进程的内存中，不写入任何文件或日志；快照恢复沿用同一密钥。
- 快照包含实例私钥与令牌，快照对象必须静态加密，读写只经 in-tree `objectstore-plugin` sidecar，atelet 与 ate-api-server 主进程不直接持有存储凭据。

承担的代价穷举如下：

- 轮换消息未送达期间，接受下界停在看守进程于 `Hello` 中出示的令牌上，可接受的令牌不只最近一张及其直接前任，直到看守进程收到新令牌组并在 `Hello` 中出示；出站流仍要求持有证明，只持有这些令牌而没有实例私钥的一方不能借此建立出站流。
- 泄露的未过期令牌在其受众与有效期内仍可使用；持有证明只覆盖 `Hello` 与工作区租约续约。
- 续约的持有证明在 `T_proof_skew` 之内可以原样重放，重放只能为同一租约续约，不能用于建立出站流。
- 每次建立出站流多一次控制面到看守进程的挑战下发，`Hello` 要等它到达才能发出。
- 领取路径多一次对 `workspace` 的调用，`workspace` 不可用时领取失败。
- 每次签发与轮换的签名数量随受众增加。

## 失效条件

- 出站流采用按沙箱实例的 mTLS 认证时，实例密钥与持有证明可由客户端证书替换。
- 控制面无需接受过期令牌的重连时，令牌接受下界可以移除。

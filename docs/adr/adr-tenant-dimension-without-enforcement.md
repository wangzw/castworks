# 保留租户维度而不实现跨租户隔离

## 背景

平台面向单组织内部使用：同一控制面上的运行实例、工作区、预热池与挂载根只服务一个组织。多个组织共用一个控制面时，数据模型与对外接口契约必须能表达记录归属的组织，平台机制还必须在组织之间隔离数据、分配配额并按优先级抢占。

运行实例记录在每次状态转移时写入，事后为它增加租户维度，需要在控制面持续服务期间迁移该表，并修改创建运行实例的接口契约（组织归属设为必填时既有调用方随之改动）。跨租户配额与抢占的正确性依赖多租户负载下的调度验证：配额核算、抢占优先级与组织间公平性只有在多个组织竞争同一容量池时才可观测。

## 考虑过的选项

### 完全不建模租户

运行实例记录不携带租户维度，创建运行实例的接口契约不含组织归属，资源归属只由运行实例与项目的标识表达。**被拒**：接入第二个组织时才增加租户维度，需要在控制面持续服务期间对高频写入的运行实例表做在线表结构迁移，并修改创建运行实例的写入路径与对外接口契约，组织归属设为必填时接口的既有调用方随之改动；预留租户维度之后，接入第二个组织只需补隔离、配额与抢占，既有记录与接口契约不变。

### 实现完整多租户隔离、配额与抢占

数据模型、鉴权、调度与预热池全部按租户划分：控制面维护租户配额账本，交付跨租户抢占与公平调度，每个租户拥有独立的预热池与挂载根。**被拒**：单组织部署下不存在第二个组织，跨租户隔离不对应任何实际存在的资源竞争或越权；配额核算、抢占优先级与组织间公平性在单组织负载下无法验证，交付的调度逻辑在出现多组织负载之前没有可观测的正确性依据；租户配额账本、跨租户抢占与按租户划分的预热池成为必须持续维护的组件。

### 保留租户维度而不实现隔离

运行实例记录与创建运行实例的接口契约携带租户维度，单组织部署下只有一个取值；不实现跨租户配额与抢占，预热池与挂载根由该组织共享。**采用**——见决策。

## 决策

采用保留租户维度而不实现跨租户隔离的方案：数据模型与创建运行实例的接口契约保留租户维度，不实现跨租户配额与抢占，预热池与挂载根为单组织共享。

## 后果

接入第二个组织时，既有记录与接口契约不需要迁移，需要补充的只有隔离、配额与抢占能力。

本决策使项目承担以下义务（穷举）：

- 运行实例记录与创建运行实例的接口契约必须携带租户维度，单组织部署下取单一值；以运行实例标识归属的记录（例如工作区、收件箱与定时器）经运行实例记录继承租户维度。
- 不实现跨租户配额与抢占；容量规划（例如预热池容量、恢复准入的限速）按单组织总量计算，不按组织划分。
- 一个控制面只服务一个组织：预热池与挂载根由该组织共享，平台机制不处理组织间的资源竞争与数据越权；接入第二个组织之前必须具备组织间的数据隔离、配额与抢占。

承担的代价穷举如下：

- 租户维度在单组织部署下只有一个取值，其传递与维护的成本不对应任何跨租户行为。
- 租户维度不构成安全边界；接入第二个组织时不能仅凭该维度完成隔离。
- 配额与抢占能力缺失，系统无法限制单个组织的资源占用，也无法在容量不足时按优先级从占用者收回资源。

## 失效条件

- 出现第二个组织要求独立资源配额、调度优先级或数据边界的接入需求。
- 单组织负载下实测出现某个工作负载持续占用容量，使其他运行实例的恢复时延超出恢复时延目标，恢复准入与挂起策略的升级梯都不能消除该影响，且消除该影响需要以租户维度划分组织内的工作负载并按划分设定配额。
- 运行实例记录中出现第二个租户取值，或出现必须写入不同租户取值的写入路径，单一取值的前提不再成立。

# 回合位置随运行实例持久化

## 背景

沙箱的生命周期短于运行实例：它可以在回合中被冻结或快照；以挂起为目的的销毁只在回合边界，其他销毁不受此限；沙箱也可以在任意时刻丢失。Agent 进程的内存状态不跨代保留，销毁重建后只能依靠 Agent 自身的会话恢复机制续接。控制面必须在沙箱不可达时判断运行实例是否应该唤醒、应该投递哪些事件，以及恢复后进入哪个子状态。

Agent 提供的信号不足以重建回合位置：L1 的 `Hello.agent_state` 只是摘要，L0 不提供回合信号；待定向的审批与 `wait_for`、正在运行的工具、当前回合标识都只存在于控制面的状态里。回合内的 LLM 流、`wait_for` 等待外部系统事件、定时等待与阻塞型审批是挂起释放资源的机会，强制所有挂起都等到回合边界会长期占住沙箱。

## 考虑过的选项

### 恢复时从 Agent 状态重新推导

采用它意味着控制面在恢复时读取 `Hello.agent_state`，由 Agent 上报的回合阶段、阻塞条件与冻结状态决定进入哪个子状态。**被拒**：`Hello.agent_state` 只是摘要，表达不了待定向目标、`call_id`、门控与在途工具集合；L0 不提供任何回合信号；控制面还要在 Agent 进程启动之前决定是否唤醒、投递什么，推导发生在错误的时机。

### 回合位置只留在沙箱内

采用它意味着回合字段只存在于看守进程或 Agent 进程的内存中，恢复时由沙箱重新上报。**被拒**：沙箱销毁后状态丢失；冻结时无法查询；控制面在挂起期间无法评估唤醒谓词与选批；重建后的新代沙箱在第一个 `Hello` 之前没有能力上报完整回合位置。

### 强制所有挂起都落在回合边界

采用它意味着只有当 Agent 结束回合、等待下一条输入时才允许挂起。**被拒**：回合内的 LLM 流、`wait_for` 等待外部系统事件、定时等待与阻塞型审批是资源释放机会；等到边界会长时间占住沙箱；L2 的显式等待点与回合内的阻塞型审批无法在边界之前释放资源。

### 回合位置作为运行实例状态跨挂起保留

采用它意味着 `turn_phase`、`blocked_on`、`pending_targets`、`running_tools`、`current_turn_id` 写入 `run` 行，非 `Active` 状态下的回合进展事件同样更新这些字段，恢复时由 `enter_active` 按字段路由。**采用**——见决策。

## 决策

采用回合位置随运行实例持久化：`turn_phase`、`blocked_on`、`pending_targets`、`running_tools`、`current_turn_id` 作为 `run` 行的回合字段跨挂起保留；非 `Active` 状态下的回合进展事件同样更新这些字段；恢复时由 `enter_active` 按字段路由到具体子状态。

## 后果

本决策使项目承担以下义务（穷举）：

- 每条影响回合位置的进展事件在 `Active` 与非 `Active` 状态下都必须按同一规则更新回合字段；非 `Active` 状态下不得做 Active 子状态转移、投递或挂起决策；`suspending` 且 `suspend_origin=active` 时，`substate` 仍须同步为与回合字段一致的 active 子状态。
- 回合字段与 `state`、`substate` 的组合必须满足闭集约束；进入 `Active` 的每条路径都必须按回合字段选择分支。
- `turn_phase`、`blocked_on`、`pending_targets`、`running_tools` 与 `current_turn_id` 的写入与清除点必须穷举（`turn_phase` 只有写入点，没有清除点），漏掉任一点会使恢复后的路由错误。
- 看守进程上报的 `agent_state` 在回合位置上不替代回合字段：`Active` 中 `phase=exited` 触发「Agent 进程退出」，`phase=boundary` 而 `turn_phase=in_turn` 时按「回合结束」对账，`frozen=true` 且冻结标识等于 `aborted_suspend_id` 时发 `Thaw`，不等于时计数、告警并执行「本代沙箱作废」；非 `Active` 状态一律按「非 Active 回合进展」对账，不做 Active 子状态转移、投递或挂起决策；其余不一致按回合字段对账或计数。
- 挂起期间到达的回合进展事件必须被持久化，不能因为沙箱不可达而丢弃。
- 销毁重建后，恢复句柄与回合字段共同决定新代的起始位置；新代 `Hello` 不得清空回合字段，代递增时只按 `fence_and_bump` 清空与旧代沙箱绑定的字段。
- L0 的 `turn_phase` 恒为 `idle`，处理中状态由 `idle_cursor` 与游标判定，不能依赖回合字段。

承担的代价穷举如下：

- `run` 行变宽，每次回合进展事件都要写控制面，回合内的事件密度直接影响数据库写入量。
- 回合字段与子状态的组合约束增多，状态机与转移表的复杂度上升。
- 回合字段与 `agent_state` 不一致时需要额外对账，且不一致本身可能无法立即判定。
- L0 的回合语义被弱化为 `idle`，部分回合级判断只能退化为游标比较。
- 恢复路径必须覆盖全部字段组合，遗漏会产生停在没有回合的 `InTurn` 或错误投递。

## 失效条件

- Agent 提供完整、持久且可查询的回合位置，控制面不需要在恢复前自行维护。

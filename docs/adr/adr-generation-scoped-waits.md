# 收件箱事件跨代保留、唤醒信号按代失效、代范围等待与定时器随代作废

## 背景

运行实例跨越多代沙箱。代递增发生在新沙箱预配之前，用于拒绝旧代沙箱的消息、令牌、工作区写入、游标推进与出口请求（[ADR-generation-fencing](adr-generation-fencing.md)）。代也划分持久化事实的生存范围：有些事实描述的是某一代沙箱内的等待，代一旦递增就不再成立；有些事实是用户或外部系统对运行实例的输入，必须在重建之后继续送达。

收件箱承载人类消息、审批决定、订阅完成与内部通知；这些事件可能在运行实例没有沙箱、正在重建或已经进入新代时到达。唤醒信号（例如 `llm_completed`、`timer_fired`、`approval_decided`）满足阻塞条件与代范围的等待条件（探测定时器、显式声明）。等待与定时器的生存范围由行上的 `scope` 决定：`scope=generation` 的等待与定时器随代作废，`scope=run` 的等待与定时器跨代保留；冻结上限处置可以把阻塞型定时等待从代范围改为运行实例范围。

## 考虑过的选项

### 所有持久化事件与条件都带代，旧代一律作废

采用它意味着收件箱事件、唤醒信号、等待与定时器都携带代，代递增时全部作废。**被拒**：人类消息与外部事件在重建期间到达时会随旧代被丢弃；以 `defer` 推迟的审批决定也会丢失；失效判定从「拒绝旧代沙箱的动作」扩大为「拒绝旧代的全部事实」，超出失效判定的目的。

### 所有事实都不带代

采用它意味着收件箱事件、唤醒信号、等待与定时器都不携带代，任何信号都可以满足任何一代的条件。**被拒**：旧代的 LLM 完成、定时器或探测信号可以满足新代的同 `ref` 条件；旧代仍在途的信号会在新代唤醒运行实例；代递增之后，旧代的等待与定时器失去意义却仍参与谓词评估。

### 只按事件种类区分，不按范围区分

采用它意味着按事件或条件的种类决定是否携带代，例如定时器统一带代、订阅统一不带代，而不区分同一类条件的范围。**被拒**：同为定时器，代范围的阻塞型 `sleep_until` 必须随代作废，运行实例范围的定时等待必须跨代保留；只按种类无法表达同一类条件的不同生存范围。

### 按事实的作用范围决定是否携带代

采用它意味着收件箱事件不携带代、跨代保留；唤醒信号与代范围的等待、定时器携带代；唤醒信号按代失效，等待与定时器随代作废；运行实例范围的等待与定时器不携带代、跨代保留。**采用**——见决策。

## 决策

采用按范围划分的代语义：收件箱事件不携带代、跨代保留；唤醒信号、代范围的等待与定时器携带代，代递增后旧代不满足新代条件；运行实例范围的等待与定时器不携带代、跨代保留。

## 后果

本决策使项目承担以下义务（穷举）：

- 收件箱事件不得因代递增而删除或作废；其清理只以 `durable_cursor` 与保留期为下界。
- 唤醒信号、代范围的等待与定时器必须携带代；代范围的等待与定时器在代递增时置 `expired`；唤醒信号不设作废状态，旧代信号由谓词的代相等条件排除，其行由清理任务按 `generation < run.generation` 删除；旧代信号不得满足新代的条件。
- 运行实例范围的等待与定时器不得携带代，且不得在代递增时作废。
- 同一 `ref` 在新代需要新的信号；旧代未消费信号不得因 `ref` 相同而被新代复用。
- 跨代重投必须从收件箱重放事件，并以投递意图日志去重（[ADR-delivery-intent-log](adr-delivery-intent-log.md)）；不得依赖旧代信号恢复投递。
- 过期行清理必须按范围分别处理：旧代信号由清理任务删除，代范围等待随代置 `expired`，收件箱事件与运行实例范围等待按保留期清理。

承担的代价穷举如下：

- 两套范围语义与两套清理规则增加实现与测试成本。
- 代范围条件在新代需要新的信号，事件源必须能为新代重新产生信号。
- 跨代事件可能重复投递，正确性依赖投递意图日志去重。
- 人类消息无法按代丢弃；即使运行实例已经重建，旧事件仍会送达。
- 收件箱清理下界受跨代重投范围约束，保留期不能随意缩短。

## 失效条件

- 所有事件都变成某一代沙箱内的私有输入，不再有跨代的用户或外部事件。
- 代不再用于替换沙箱，运行实例始终由同一个沙箱承载。

# 挂起机制按提供者能力分层

## 背景

沙箱提供者的能力不同。k8s 提供者可以冻结（`Freeze{cgroup}` 或 `Freeze{signal}`）、销毁、使用预热池与原地缩小 CPU request（[REF-agent-sandbox](../references.md)、[REF-linux-cgroup-v2](../references.md)、[REF-k8s-in-place-pod-resize](../references.md)）。Substrate 提供者可以快照、销毁与落地出口策略（`EgressInject`），新建 actor 从[模板快照](../glossary.md)恢复，但不具备冻结能力与预热池（[REF-substrate](../references.md)）。同一套挂起策略要在 k8s 提供者与 Substrate 提供者上运行，并在能力缺失时退化。

没有一种机制同时满足全部等待形态：冻结保留内存且恢复最快，但不释放内存；快照释放全部资源，但恢复时延为秒级且成本更高；销毁重建释放资源，但丢失回合上下文并拉长恢复；原地缩小只降低 CPU request，不释放内存。内核级检查点恢复（CRIU）需要特权与内核兼容性，不能作为跨运行时的默认机制（[REF-criu](../references.md)）。

## 考虑过的选项

### 绑定单一机制

采用它意味着控制面只实现一种挂起机制，所有提供者与所有等待形态都使用它。**被拒**：只冻结无法释放内存；只快照对短等待而言过慢且成本高；只销毁重建丢失回合上下文并拉长恢复；只冻结、只快照与只销毁重建各自都不能覆盖全部等待形态，绑定其中一种会把其他形态的代价转嫁给用户。

### 每个提供者各自决定机制

采用它意味着每个沙箱提供者自行选择挂起与恢复方式，控制面不定义统一机制。**被拒**：策略无法跨提供者共用；能力缺口会泄漏到状态机，`runcontroller` 必须为每个提供者写分支；新增提供者要改控制面，扩展点不再存在。

### 依赖内核级检查点恢复（CRIU）

采用它意味着所有沙箱都用 CRIU 做进程级检查点与恢复，不区分冻结、快照与销毁。**被拒**：CRIU 需要特权与内核兼容性，不是所有运行时都支持；在容器编排环境中的可用性不足以让它成为默认机制；它与现有提供者的快照、冻结能力重复，且引入新的故障模式。

### 能力集合与闭集机制，策略在能力内选择

采用它意味着挂起机制是闭集，沙箱提供者以能力集合自描述，策略只在能力允许的机制中选择；`Freeze{signal}` 只允许短冻结。**采用**，见决策。

## 决策

采用按提供者能力分层的挂起机制。挂起机制是闭集，即不挂起、冻结（可附带原地缩小 CPU request）、快照、销毁重建；沙箱提供者以能力集合自描述，挂起策略只在能力允许的机制中选择；`Freeze{signal}` 只允许短冻结。

## 后果

本决策使项目承担以下义务，穷举如下：

- 沙箱提供者必须自描述能力集合；策略不得选择提供者未声明支持的机制。
- 每个机制必须有明确的恢复路径、超时、失败处置与代价，且能被恢复准入按机制限速。
- `Freeze{signal}` 只允许短冻结；冻结上限到达时必须离开冻结。静止冻结直接唤醒并恢复运行；其余冻结中，可升级的等待经快照升级，不能升级的按 `DRAIN` 处置离开冻结（`DRAIN` 是 `suspendpolicy.review` 的返回值与离开冻结后的处置，不是挂起机制）。销毁由两种情形选定：一是在回合边界的冻结中复评（例如宽限期到期，且回合边界与 I9 成立），二是在 `DRAIN` 之后的排空完成。它不是冻结上限的升级结果。非阻塞的第三方工具调用不进入由阻塞条件触发的冻结路径，只在静止证据成立时随 Agent 进程树静止冻结。
- Substrate 路径在回合中只有不挂起与快照；回合边界仍可销毁重建；后台作业存活期间没有静止冻结可用，只能不挂起。
- 能力缺失时的退化路径必须纳入设计，不能把能力缺口留给运行时错误。
- 新增提供者或新增机制必须同时扩展能力集合、机制闭集、策略选择与测试矩阵。

承担的代价穷举如下：

- 要实现并验证多种机制，能力矩阵与组合测试增多。
- `Freeze{signal}` 的短冻结限制需要策略与看守进程共同维护，跨模块约束更强。
- 提供者能力变化会影响策略的可选机制集合，策略参数需要按能力调整。
- 某些提供者在某些状态下只能选择成本更高的机制，或无法挂起。
- 机制之间的恢复时延不同，恢复准入与用户体验需要按机制分别设定预期。

## 失效条件

- 出现一种机制，在所有提供者上同时满足内存释放、恢复时延与成本目标，其他机制不再需要。
- CRIU 或等价的检查点恢复成为所有运行时的默认能力，且不引入特权或兼容性约束。

# 同时实现 k8s 与 Substrate 两个沙箱提供者

## 背景

没有单一沙箱提供者同时覆盖冻结与快照：k8s 提供者基于 kubernetes-sigs/agent-sandbox（[REF-agent-sandbox](../references.md)），可以冻结、销毁、使用预热池与原地缩小 CPU request（[REF-k8s-in-place-pod-resize](../references.md)），但不能快照；Substrate 提供者（[REF-substrate](../references.md)）可以快照、销毁与落地出口策略，新建 actor 从[模板快照](../glossary.md)恢复，但没有轻量冻结。

系统的恢复时延与资源利用率目标需要冻结与快照两类挂起机制：短等待用冻结，恢复在百毫秒级且保留进程状态；长等待用快照，释放内存且保留进程状态。回合边界用销毁重建，释放全部资源。只有其中一类机制时，另一类等待只能选择代价更高的路径。

Substrate 处于 v1.0.0-rc.1，能力与稳定性尚未验证；k8s 路径依赖节点冻结代理与原地缩放，尚未在目标集群验证。两个提供者应当共用看守进程、协议与控制面，把差异留在提供者子模块内。

## 考虑过的选项

### 仅实现 Substrate 提供者

采用它意味着只交付快照与销毁两条路径，短等待没有冻结可用，回合中的等待只能快照或销毁。**被拒**：短等待的快照恢复是秒级，达不到解冻路径的时延目标；没有冻结层，回合中的长等待只能靠快照或销毁。

### 仅实现 k8s 提供者

采用它意味着只交付冻结与销毁两条路径，长等待只能冻结到上限后升级到销毁。**被拒**：冻结保留内存，长等待在冻结上限之前一直占住内存；超过上限只能销毁，丢失回合上下文并拉长恢复；原地缩小只降低 CPU request，不释放内存；无法覆盖需要释放内存又保留进程状态的长等待。

### 基于 Google AX 构建

采用它意味着以 AX（[REF-google-ax](../references.md)）的 Task、Workspace、Model 资源与 Substrate actor 生命周期为开发基础。**被拒**：Task 是一次性命令模型，没有事件、审批与订阅通道；凭据以环境变量进入沙箱，与沙箱零凭据冲突；卷恢复时重跑 prompt，不能续接被中断的回合；版本自述有破坏性变更。只借鉴其 runner 契约与「只存自己写的状态、运行态从底层读」的原则。

### 两个提供者并存，共用看守进程、协议与控制面

采用它意味着同时实现 k8s 提供者与 Substrate 提供者；两个提供者共用看守进程、协议与控制面，差异留在提供者子模块；能力集合与策略选择按 [ADR-capability-tiered-suspension](adr-capability-tiered-suspension.md) 处置。**采用**——见决策。

## 决策

采用两个沙箱提供者并存：k8s 提供者覆盖冻结、销毁、预热池与原地缩小 CPU request，Substrate 提供者覆盖快照、销毁与出口策略，新建 actor 从模板快照恢复；两个提供者共用看守进程、协议与控制面，挂起策略按提供者能力分层（[ADR-capability-tiered-suspension](adr-capability-tiered-suspension.md)）。

## 后果

本决策使项目承担以下义务（穷举）：

- 提供者接口必须覆盖预配、冻结与解冻、快照与恢复、按代销毁、预热池认领、原地缩放、节点压力查询、出口策略的落地与撤销，以及能力集合。
- 同一套看守进程镜像、协议与控制面代码必须能在两个提供者上运行；提供者特有行为留在各自子模块。
- 能力差异与退化路径按 [ADR-capability-tiered-suspension](adr-capability-tiered-suspension.md) 处置。
- 每个提供者必须有独立的集成测试。
- 提供者特有的安全机制必须各自落地：k8s 的节点冻结代理为特权 DaemonSet，Substrate 的出口策略与凭据提供者按 actor 落地。

承担的代价穷举如下：

- 两套提供者实现与两套运维模型，测试矩阵与排障面扩大。
- Substrate 处于候选版本，能力与稳定性尚未验证，可能需要返工或重做快照路径。
- 能力缺口导致同一工作负载在两个提供者上的挂起与恢复行为不同，用户可感知的恢复时延不同。
- 共用抽象要同时容纳两种提供者，存在被拉向能力交集的风险。
- 单提供者部署无法覆盖全部等待形态。

## 失效条件

- 某个提供者补齐缺失能力（k8s 快照或 Substrate 冻结）且成熟度与成本可接受时，另一个提供者不再是必需。
- 工作负载不再需要冻结或快照中的一类，单提供者足以覆盖全部等待形态。
- Substrate 提供者在实际负载下不能达到稳定性要求，且无法以可接受代价解决时，本决策不再成立。

# 活动度样本以不进入可靠序号的遥测帧发送

## 背景

[看守进程](../glossary.md)按周期 `T_activity` 在[出站流](../glossary.md)上发送 `Activity`，即 Agent 进程树的活动度样本。样本里有两类字段：累计量，例如 PSI 的停滞累计时间、CPU 用量、被限流时间、IO 与网络字节数，相邻样本之差就是这段时间内的量；瞬时值，例如各状态的进程数、定时睡眠的进程与冻结状态。`suspendpolicy` 依据相邻样本之差在静默窗口内判定静止证据与空闲证据。

控制面只在持有出站流的所有者副本内存中保留活动度摘要，不持久化；所有权转移后，新所有者的累计从零起算（[ADR-single-writer-per-run](adr-single-writer-per-run.md)）。

看守进程发往控制面的应用消息（握手、关闭、确认与遥测之外的消息）跨连接可靠：控制面在每条消息的处理事务中提交 `run.in_msg_seq`，接收方串行处理，未确认消息的条数与字节数受窗口上限约束，窗口满时看守进程的新消息进入待发队列（[ADR-asymmetric-stream-replay](adr-asymmetric-stream-replay.md)）。

## 考虑过的选项

### 与应用消息共用序号与窗口

采用它意味着 `Activity` 与其他看守进程消息一样分配序号、进入重放缓冲、等待确认并在重连后重放。**否决**：每个样本都要一次提交 `run.in_msg_seq` 的处理事务，每个运行实例每 `T_activity` 一次数据库写入，而样本本身只进内存；串行处理使样本与应用消息互相排队；出站流不可用期间样本占用应用消息需要的窗口，重连后重放的旧样本又立即被下一个样本取代。

### 为遥测另开一条流

采用它意味着看守进程另建一条只承载活动度样本的流，与出站流分开确认与流控。**否决**：活动度摘要只在持有出站流的所有者副本内存中，另一条流可能落到别的副本上，样本还要转发给所有者；这条流也要自己的令牌认证、持有证明与连接生命周期。

### 以不占序号、不确认、不重放的遥测帧发送，样本自带序号与采样时刻

采用它意味着 `Activity` 不进入可靠序号，流不可用时直接丢弃；样本带看守进程内单调递增的样本序号与采样时刻，接收方按样本序号丢弃过时样本，按采样时刻计算区间。**采纳**，见决策。

## 决策

采用把 `Activity` 作为遥测帧发送：

- `Activity` 不占出站流的序号，不进入重放缓冲，不确认，不重放，不计入窗口；出站流不可用时直接丢弃，重连后从下一个周期继续。
- 每个样本带 `sample_seq`（看守进程内单调递增）与 `sampled_at`（采样时刻，取看守进程校时后的时间）。接收方丢弃 `sample_seq` 不大于已收到最大值的样本。
- 累计量字段相邻两个已收到样本之差除以 `sampled_at` 之差即区间速率；`suspendpolicy` 以 `sampled_at` 计算采样窗口的时长，不以到达时刻计算。

## 后果

本决策使项目承担以下义务，穷举如下：

- `Activity` 中用于速率与静默判定的字段必须是累计量，使中间丢失的样本不影响区间速率的正确性。
- `suspendpolicy` 的活动度摘要以 `sampled_at` 为样本时刻；当前时刻只用于与 LLM 时刻字段这类非采样量的比较。
- 看守进程的 `sampled_at` 依赖它按服务端时刻所做的校时（[ADR-run-token-audience-and-holder-binding](adr-run-token-audience-and-holder-binding.md)）。

承担的代价穷举如下：

- 出站流中断期间没有样本到达，依赖活动度的静止证据与空闲证据在中断期间不更新；重连后的首个样本与中断前最后一个样本之差覆盖整个中断区间，只能给出这一区间的平均速率。
- 瞬时值只在收到的样本上可见，丢失样本所在时刻的进程状态、定时睡眠与冻结状态无从得知。

## 失效条件

- 静止证据或空闲证据的判据改为依赖逐个样本的瞬时值，不能由累计量之差得出时，丢失样本会改变判定结果，本决策的前提不再成立。

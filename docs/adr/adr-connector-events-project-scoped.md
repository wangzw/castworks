# 连接器事件与订阅按项目归属键隔离

## 背景

[连接器事件日志](../glossary.md)以 `(system, delivery_id)` 为唯一键，在部署内共享；webhook 接收路径由部署统一提供，一个[外部系统定义](../glossary.md)接收所有项目的事件，例如一个 GitHub App 安装覆盖组织内多个项目的仓库。[订阅](../glossary.md)由 Agent 显式给出关联键，平台按外部系统和关联键做回溯匹配与实时匹配（[ADR-platform-does-not-execute-external-operations](adr-platform-does-not-execute-external-operations.md)），同一关联键下的多个订阅共享事件；项目之间的隔离由本决策规定。

受提示注入控制的 Agent 可以在登记订阅时填写任意关联键。订阅登记不核对项目且匹配只看关联键与过滤条件时，任一[运行实例](../glossary.md)都能订阅其他项目的外部对象（例如另一个项目仓库中的 Issue），经回溯匹配取得已到达的事件，再经附件取回读取原始 webhook 负载。附件取回只核对附件是否属于本运行实例订阅的完成事件，挡不住这一路径。

## 考虑过的选项

### 依赖关联键精度隔离

采用它意味着事件日志与订阅都不带项目维度，隔离依赖关联键与关联键身份键的精度。**被拒**：关联键由 Agent 填写，任一运行实例可以订阅其他项目的对象并取回原始负载。

### 每个项目独立的 webhook 路径与签名密钥

采用它意味着每个项目在外部系统中配置独立的 webhook 地址与签名密钥，事件按接收路径归属项目。**被拒**：GitHub App 与组织级 webhook 把多个仓库的事件投递到同一地址；按项目拆分须在外部系统中为每个项目单独配置，共享的外部系统定义无法复用。

### 按运行实例隔离事件日志

采用它意味着事件按运行实例落盘，订阅只匹配本运行实例的事件。**被拒**：事件到达时可能尚无任何订阅，无法确定其归属的运行实例；同一项目的多个订阅共享事件，回溯匹配也跨订阅，需要共享的日志。

### 外部系统定义声明项目归属键，项目配置声明绑定值

采用它意味着外部系统定义声明关联键中哪个字段决定项目归属，项目配置声明本项目拥有的取值；事件写入时计算所属项目，订阅只匹配本项目的事件。**采用**——见决策。

## 决策

采用连接器事件与订阅按[项目归属键](../glossary.md)隔离：

- 外部系统定义以 `events.project_binding` 声明[项目归属键](../glossary.md)，取值为关联键中的一个字段路径；带 webhook 事件源的定义缺少它时不装载。
- 项目作用域配置声明每个项目拥有的绑定值；同一取值出现在多个项目中时，视为显式共享。
- webhook 摄入在签名校验之后、在写入连接器事件日志的同一事务内，按规范化后的归属键取值计算事件所属的项目集合 `project_ids`；项目集合为空的事件照常落盘审计，不参与任何匹配。
- 连接器事件日志在存储上部署级共享，每条事件带所属项目集合。
- 订阅带项目字段，取值来自令牌所属运行实例的项目，不接受调用方传入；登记时校验外部系统属于本项目可用的外部系统，关联键中含归属键时其取值须属于本项目的绑定值，不满足时拒绝并审计。
- 回溯匹配、实时匹配与订阅对账扫描都要求事件的项目集合包含订阅的项目。
- 附件取回另要求附件所属事件的项目集合包含令牌所属运行实例的项目。

## 后果

本决策使项目承担以下义务，穷举如下：

- 带 webhook 事件源的外部系统定义必须声明 `events.project_binding`。
- 每个项目维护绑定值清单；同一外部对象在多个项目间共享时，须在各项目中显式列出。
- 无法归属的事件只审计，不参与匹配。
- 连接器事件日志的倒排索引以项目作为键的一部分。

承担的代价穷举如下：

- 项目配置须随仓库或外部对象的增减而维护。
- 倒排索引多一维，索引体积增加。
- 遗漏绑定值的外部对象，其事件无法被任何订阅命中。

## 失效条件

- 外部系统按项目提供独立的事件投递通道与签名时，项目归属可由投递通道确定，无需项目归属键。
